# Browser Copilot

[English](README.md) · **简体中文**

一个 Chrome 扩展（Manifest V3），在浏览器侧边栏放一个能读取当前网页的 AI 助手。
支持任意 OpenAI 兼容的模型——DeepSeek、火山方舟、OpenAI、本地 Ollama 等等。

它只读取和给建议，不会点击、输入或跳转；也不会定时运行——每次动作都是对你刚才操作
的回应。

## 能用来做什么

用法始终是同一个模式：打开一个页面，就这个页面提问。下面是它擅长的场景——每一条都
附上了老实话，因为知道一个工具的边界在哪，才用得顺手。

### Review PR（代码评审）

打开 PR 的 **Files changed** 页面，让它评审——逻辑错误、遗漏的边界情况、命名，以及
改动是否与描述相符。

> 评审这个 diff，重点看错误处理，以及有没有可能影响现有调用方。

**先选中你关心的那段代码，效果最好。** 选中的文字会与页面正文分开采集，所以高亮某个
函数能给模型一个精确目标，而不是整个 diff。这一点很关键，因为 GitHub 会把大 diff 折叠
在 "Load diff" 按钮后面——扩展只能看到**实际已渲染**的内容，且页面文本上限约 12,000
字符（中文约 6,000–10,000 字）。所以大 PR 请分几个文件多次评审，不要指望一次读完。

它无法在文件间跳转，也无法替你发表评论。它读你正在看的那个标签页，动手的是你。

### 总结网页

长文章、技术文档、release notes、论坛长帖、论文。

> 用五条要点总结，然后列出作者没有给出证据就断言的部分。

这是最稳的场景：一个页面、一次读取、一个答案。任何普通 http(s) 页面都可以。

### 看懂陌生代码或文档

打开 GitHub 上的某个文件、API 参考或规范，让它按你需要的深度解释。

> 解释这个模块做什么，以及为什么可能这样设计。

> 满足这个 API 的最小请求是什么样的？

### 分析页面上的数据

仪表盘、HTML 表格、查询结果、日志输出、定价页。

> 这几个季度的趋势是什么，哪一行是异常值？

**这里要提醒一句。** 模型拿到的是**文本形式**的表格，它是在推理，而不是在计算。语言
模型对长表格做算术并不可靠，所以任何数字都应视为**待验证的假设**，而不是计算结果。
建议追问依据（"你是根据哪几行得出的？"），而不是只要一个总数。

### 翻译与改写

> 把这个页面翻译成中文，技术术语保留英文。

> 把这段改写成非专业人士能看懂的表达。

### 按团队规范检查

配合[技能](#技能skills)使用：把团队的检查清单存成技能——评审规范、安全检查清单、
文案风格指南——就能对每个页面套用同一套标准，不必反复粘贴。

### 做不到的事

| 不支持 | 原因 |
| --- | --- |
| 填表单、点按钮、跳转页面 | 设计上只读：它观察，你操作。 |
| 同时读多个标签页 | 它读你正在看的那一个，一次一读。 |
| 读 `chrome://`、本地文件、应用商店页面 | Chrome 禁止扩展注入这些页面，任何权限都改不了。 |
| 读 iframe 内的内容 | 只读顶层框架（内嵌播放器、部分评论组件读不到）。 |
| 执行代码或做计算 | 它基于文本推理，见上面数据分析的提醒。 |
| 定时自动运行 | 没有定时器，也没有 `alarms` 权限。 |

## 安装

需要 **Node.js 20+** 和 **Chrome 116+**。

```bash
git clone git@github.com:dcc123456/browser-copilot.git
cd browser-copilot
pnpm install
pnpm run build
```

然后加载到 Chrome：

1. 打开 `chrome://extensions`。
2. 打开右上角的**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择构建出来的 **`dist/`** 目录。
4. 点击工具栏上的扩展图标，打开侧边栏。

习惯用 npm 的话，`npm install && npm run build` 同样可以。

这里不提供预打包下载：那样的包未签名、未经审核，从源码构建是更诚实的分发方式。

### 更新

```bash
git pull
pnpm install
pnpm run build
```

然后在 `chrome://extensions` 的扩展卡片上点**重新加载**。仅重新构建不会刷新已加载的
service worker。

## 支持哪些模型

任何遵循 OpenAI chat-completions 协议的端点。扩展内部**没有任何厂商专属代码**——一个
provider 只是配置，不是一条代码分支——所以下面没列出的端点同样能用，只要它接受
`POST {baseUrl}/chat/completions`、`Bearer` 认证和 SSE 流式返回。

下列预设只是帮你省去输入 URL，每个字段都可以改。

| 预设 | 接口地址（Base URL） | 模型示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat`、`deepseek-reasoner` |
| 火山方舟 Volcengine Ark | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seed-code`，或接入点 ID `ep-…` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `deepseek/deepseek-chat` |
| Moonshot / Kimi | `https://api.moonshot.cn/v1` | `kimi-k2-0905-preview` |
| 阿里云百炼 DashScope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 硅基流动 SiliconFlow | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` |
| Ollama（本地） | `http://localhost:11434/v1` | `qwen3:8b` |
| LM Studio（本地） | `http://localhost:1234/v1` | `local-model` |
| 自定义 | — | 任意 OpenAI 兼容端点 |

### 怎么选模型

**关键是支持 function calling（工具调用）。** 助手是通过调用工具来读取页面的，所以
不支持工具调用的模型可以正常聊天，但永远不会主动读页面。此时手动勾选"附带当前页面"
仍然有效——弱一些的模型依然可用，只是不够省事。

- **日常使用** —— `deepseek-chat`、`gpt-4o-mini`、`qwen-plus`：快且便宜。
- **代码评审、复杂推理** —— `deepseek-reasoner`、`doubao-seed-code`。
- **长页面** —— 优先选上下文窗口大的模型；页面文本上限约 12,000 字符，但对话历史会在
  此之上继续累积。
- **本地 / 隐私优先** —— Ollama 或 LM Studio，页面内容完全不出本机。请选支持工具调用
  的模型（例如较新的 Qwen），并接受响应更慢。

## 如何配置模型

打开侧边栏 → **设置** → **添加模型服务**。

1. **选一个预设。** 接口地址和建议模型会自动填好。
2. **粘贴 API 密钥。** 到对应平台获取：
   [DeepSeek](https://platform.deepseek.com/api_keys) ·
   [火山方舟](https://console.volcengine.com/ark) ·
   [OpenAI](https://platform.openai.com/api-keys) ·
   [OpenRouter](https://openrouter.ai/keys) ·
   [Moonshot](https://platform.moonshot.cn/console/api-keys) ·
   [百炼](https://bailian.console.aliyun.com/) ·
   [硅基流动](https://cloud.siliconflow.cn/account/ak)。
   本地 Ollama 或 LM Studio 填任意非空字符串即可。
3. **填模型。** 手动输入，或点**获取模型列表**让端点返回可用模型。不是所有网关都实现
   了 `/models`，所以手动输入永远是有效做法。
4. **点"测试连接"。** 它会发一次真实请求，同时验证**密钥和模型**是否都可用——比回答
   到一半才发现拼错要好得多。
5. **保存。**

### 各字段说明

| 字段 | 说明 |
| --- | --- |
| **名称** | 你自己给这份配置起的名字，例如"方舟 coding plan"。 |
| **接口地址** | 到 `/chat/completions` **之前**为止的部分。要保留版本段（`/v1`、`/api/v3`）——各厂商不一致。粘贴完整地址会被自动裁剪。 |
| **API 密钥** | 以 `Authorization: Bearer …` 发送。 |
| **模型** | 模型 ID；方舟上也可以填专用接入点 ID（`ep-…`）。 |
| **温度** | 可选。留空则用服务端默认值。 |
| **最大 token 数** | 可选的回复长度上限。留空由服务端决定。 |
| **额外请求头（JSON）** | 可选，供需要归属或路由头的网关使用。 |

### 配置多个服务

可以添加任意多个，用**使用这个**切换——评审用强模型、总结用便宜的、涉及敏感内容时
用本地的。凭据按配置分别保存，切换不需要重新输入密钥。

### 密钥存在哪

存在 `chrome.storage.local`，**仅本机**。刻意没有用 `storage.sync`——那会把密钥同步到
你登录过的每一个浏览器。

它**没有加密**：任何能读取你浏览器配置目录的人都能读到。对于没有主密码机制的扩展，
这是常态——如果某个密钥不能接受这种风险，请改用本地模型。

## 使用说明

### 对话

输入后按 **Enter** 发送（**Shift+Enter** 换行）。

勾选**附带当前页面**，就会把你正在看的页面随消息一起发送。

可以随时关闭侧边栏：回答会在后台继续，重新打开时会恢复对话记录，并接回仍在进行中的
回复。

回复以 Markdown 渲染——标题、列表、表格，代码块带复制按钮。而**你自己输入的内容**
保持原样显示。

### 读取页面的两条路径

- **你主动附带。** 勾选"附带当前页面"，不会弹确认——你已经指明了是哪一页、什么时候。
  在这条消息的后续处理中，助手也可以不再询问就重新读取该页面，因为你已经授权过了。
- **助手主动请求。** 对于你**没有**附带的页面，模型发起的读取会先弹确认。

这个不对称是刻意设计。当前标签页可能是邮箱、内部系统或银行账单，读取意味着把这些文字
发给第三方模型。你主动附带是明确同意；模型自己决定则不是。

附带带来的免确认**仅限那一个页面**，按 origin 和路径比对（忽略 query string 和
`#fragment`，因此单页应用改写 URL 不会重复弹确认）。如果回答过程中你切到了别的页面，
下一次读取会重新询问——你的授权只覆盖了一个页面，而不是从此以后的任意页面。凡是无法
确证为同一页面的情况（包括 URL 未知的标签页）都会重新弹确认。

**设置 → 页面读取权限 → 检测当前标签页**可以在你依赖它之前，先告诉你这个页面能不能读。

### 界面语言

**设置 → 语言**：English、简体中文，或**自动**（跟随浏览器）。面板语言与 Chrome 自身
的界面语言无关——很多人用英文 Chrome，但希望面板是中文。

### 外观主题

面板会**跟随操作系统**的浅色 / 深色主题，切换系统主题后立即生效，无需刷新。

面板里刻意**没有**主题切换开关。Chrome 并未向扩展提供读取"浏览器主题"的接口，能拿到的
只有操作系统层面的偏好。因此手动开关会变成第二个数据源，可能与面板所依附的浏览器窗口
不一致。

两套主题都由测试套件按 WCAG AA 标准（4.5:1）校验对比度——在深色下好看的颜色，放到白色
背景上往往不达标。

## 技能（Skills）

技能就是一段存下来的指令包——把提示词里**不变**的那部分固定下来。

**技能 → 新建技能**，填名称、一句话说明适用场景、以及具体指令。然后二选一：

- 在输入框打 **`/`** 手动选择，或
- 保持"允许 agent 自动应用"开启，当你的消息与说明相符时它会自行使用。

适合用来存代码评审清单、你固定想要的总结格式、翻译术语表，或数据提取的字段结构。

前期只把名称和说明提供给模型，完整指令按需加载——所以十个技能不会让每次请求都背上
十份指令正文。

## 隐私与权限

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存设置、模型服务配置和技能。 |
| `tabs` | 知道当前是哪个标签页，读取其标题和 URL。 |
| `scripting` | 在你要求读取页面时，注入一次性的只读采集脚本。 |
| `sidePanel` | 显示侧边栏。 |
| `http(s)` 的 `host_permissions` | 读取页面文字，以及请求你配置的模型端点。 |

**特意没有**：`alarms`（不做任何定时任务），以及常驻的 content script——在你要求读取
之前，不会向任何页面注入内容。

**会离开你电脑的数据**：你的消息，以及你附带或批准读取的页面文字，发往**你自己配置的**
模型端点。除此之外没有别的数据、也没有别的去处。没有埋点、没有统计分析，本项目不存在
任何服务器。

**对话记录**存在 `chrome.storage.session`——基于内存，浏览器关闭即清空，因此采集到的
页面文字不会落盘。只保留最近 200 条消息。

## 开发

```bash
pnpm run dev         # 改动即重新构建
pnpm run typecheck   # tsc --noEmit
pnpm run test        # vitest —— 245 个测试
pnpm run build       # 生产构建输出到 dist/
pnpm run icons       # 重新生成 public/icons
```

改动 service worker 后，需在 `chrome://extensions` 点**重新加载**。

```
src/
  background/
    index.ts      Service worker：命令通道 + 流式 agent 端口
    agent.ts      工具定义、工具调用循环、确认门控
    page.ts       通过一次性脚本注入读取当前标签页
    keepalive.ts  引用计数的 worker 保活，覆盖进行中的回答
  lib/
    llm.ts        OpenAI 兼容的流式客户端 + SSE 累加器
    providers.ts  模型服务配置、预设、校验
    storage.ts    chrome.storage 访问：设置、技能、对话记录
    messages.ts   面板 ↔ worker 的通信协议
    pages.ts      判定哪些 URL 允许读取
    extract.ts    空白折叠与长度截断
    skills.ts     技能校验与提示词组装
    slash.ts      输入框斜杠命令解析
    markdown.ts   Markdown 解析器，输出类型化语法树（不产生 HTML）
    i18n.ts       文案词典
  sidepanel/      React 界面：对话、技能、设置
```

改代码前值得知道的两个设计决定：

**Markdown 解析成语法树，绝不生成 HTML。** 助手的输出是**不可信输入**（模型可能刚读过
一个被攻击者控制的页面），而侧边栏是**特权环境**（这里的脚本能访问存放密钥的
`chrome.storage`）。因此全程不拼接任何 HTML 字符串，代码中不存在
`dangerouslySetInnerHTML`——注入在结构上就不可能，而非依赖"消毒是否写对"。链接目标按
协议**白名单**校验。

**所有需要持久化的数据都在 `chrome.storage`。** MV3 的 service worker 空闲约 30 秒就
会被回收，模块级变量会一起消失。此外每次回答还会持有一个引用计数的保活——因为关闭侧边栏
会销毁那个"让 worker 保持唤醒"的端口，而回答途中关闭面板是被支持的操作。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 提示未配置模型服务 | 设置 → 添加模型服务。 |
| 401 / 403 | 密钥错误或已过期，或密钥与接口地址不属于同一家厂商。 |
| 发送时 404 | 接口地址少了版本段（`/v1`、`/api/v3`），或模型名不存在。点**测试连接**可以快速定位。 |
| 提示无法读取此页面 | 这是 `chrome://`、`file://`、应用商店或其他扩展的页面，任何权限都无法解决。 |
| 页面文字为空或不全 | 内容在 iframe 里、在读取之后才渲染，或藏在"加载更多"后面。刷新重试，并先选中你关心的部分。 |
| 助手能聊天但从不读页面 | 模型不支持 function calling。改为手动勾选"附带当前页面"，或换模型。 |
| 长页面像是被截断了 | 确实被截断了：上限约 12,000 字符。请先选中关键段落。 |
| 点工具栏图标没反应 | 在 `chrome://extensions` 重新加载扩展，可能是 worker 启动失败。 |
| 本地模型拒绝请求 | 确认本地服务已启动，且接口地址以 `/v1` 结尾。 |

## 已知限制

- 只读：不会点击、输入、跳转或提交表单。
- 一次一个标签页，且只读顶层框架。
- 页面文本上限约 12,000 字符；截断这件事会告知模型，所以它会说明，而不是自己编。
- 每轮对话的工具调用最多 5 轮，防止模型陷入循环。
- 让模型自主读取页面需要支持 function calling 的模型。
- 端点必须接受来自浏览器扩展的请求。公开 API 都可以；对来源检查严格的内网网关可能不行。
- 对话记录在浏览器关闭时清空，这是设计如此。
