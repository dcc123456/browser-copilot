# Browser Copilot

[English](README.md) · **简体中文**

一个 Chrome 扩展（Manifest V3），在浏览器侧边栏放一个 AI 助手。它不仅能**读取当前
网页，还能直接在页面上操作**——点击、输入、滚动、切换标签、填写表单；支持任意
OpenAI 兼容的模型——DeepSeek、火山方舟、OpenAI、本地 Ollama 等等。

它替你做多少，完全由你决定。三种模式可以让你把每一次点击都握在手里、把整段任务交给
它、或保持完全只读。它不会定时运行——每一个动作都是在执行你刚才提出的请求。

## 能用来做什么

它最适合"任务发生在一个页面上、又需要读和操作结合"的场景。每条都附上老实话，因为知道
工具的边界才用得顺手。

### 填写表单、套用已保存的信息

> 用我保存的资料填这个注册页，密码字段用工作邮箱那条凭据。

它可以在输入框打字、选择下拉项、勾选复选框并提交。保存的资料用来填姓名/邮箱/电话/地址；
保存的密码会**直接填进目标字段，模型自始至终看不到密码值**。

### 走完一段多步操作

> 把这件商品加入购物车，并用保存的地址结账。

它能点按钮和链接、等待跳转、滚动以露出更多内容、打开/切换标签来跟随流程。**全自动**下
它会一路执行；**半自动**下每个动作都先给你确认。

### 评审 PR（代码评审）

打开 PR 的 **Files changed** 页面，让它评审——逻辑错误、遗漏的边界情况、命名，以及改动
是否与描述相符。

> 评审这个 diff，重点看错误处理，以及有没有可能影响现有调用方。

**先选中你关心的那段代码，效果最好。** 选中的文字会与页面正文分开采集，所以高亮某个函数
能给模型一个精确目标，而不是整个 diff。GitHub 会把大 diff 折叠在 "Load diff" 按钮后面
——扩展只能看到**实际已渲染**的内容，且页面文本上限约 12,000 字符。

### 总结网页

长文章、技术文档、release notes、论坛长帖、论文——一个页面、一次读取、一个答案。任何普通
http(s) 页面都可以。

> 用五条要点总结，然后列出作者没有给出证据就断言的部分。

### 看懂陌生代码或文档

打开 GitHub 上的文件、API 参考或规范，让它按你需要的深度解释。

> 解释这个模块做什么，以及为什么可能这样设计。

### 分析页面上的数据

仪表盘、HTML 表格、查询结果、日志输出、定价页。

> 这几个季度的趋势是什么，哪一行是异常值？

**这里要提醒一句。** 模型拿到的是**文本形式**的表格，它是在推理，而不是在计算。语言模型
对长表格做算术并不可靠，所以任何数字都应视为**待验证的假设**。建议追问依据（"你是根据哪
几行得出的？"），而不是只要一个总数。

### 翻译改写、按团队规范检查

配合[技能](#技能skills)使用：把团队的检查清单存成技能——评审规范、安全检查清单、文案风格
指南——就能对每个页面套用同一套标准，不必反复粘贴。

### 做不到的事

| 不支持 | 原因 |
| --- | --- |
| 在**只读模式**下操作页面 | 该模式移除了所有操作工具，并拒绝任何点击/输入/跳转；切到半自动或全自动即可。 |
| 读 `chrome://`、本地文件、应用商店页面 | Chrome 禁止扩展注入这些页面，任何权限都改不了。 |
| 绕过验证码或凭空替你登录 | 它能填你保存的凭据，但无法解验证码或绕过二次验证。 |
| 保证长表格计算正确 | 它基于文本推理而不是计算，见上面数据分析的提醒。 |
| 定时自动运行 | 没有定时器，也没有 `alarms` 权限。 |

## 代理模式

在聊天框左下角的下拉框选择模式。选择会作用于**下一个动作**——包括已经在进行中的回答里
的后续动作，所以你可以在任务中途切换并立即生效。

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| 🔒 **只读** | 不点击、不输入、不跳转、不切换标签、不填写，只能读取。 | 评审、总结、翻译等希望零副作用的场景。 |
| 🛡 **半自动**（默认） | 每个改变页面的动作都先展示给你确认或拒绝；已附带页面的读取不再询问。 | 日常使用；每一步都在你掌控之中。 |
| ⚡ **全自动** | 读取和写入操作都不再确认直接执行。首次切换时会弹警告。 | 你信任它自行完成的、重复性的、明确的流程。 |

下拉框旁边的 ℹ️ 图标会说明当前模式。半自动下，确认卡片会准确显示它要做什么（点哪个按钮、
填哪个字段、打开哪个 URL）。全自动下，相同的动作仍会记录在**数据**标签的操作历史里，事后
可审计。

## 安装

需要 **Chrome 116+**（或任何支持 Manifest V3 侧边栏的 Chromium 浏览器）。

### 方式一：下载发行版

1. 前往 [**Releases**](https://github.com/dcc123456/browser-copilot/releases)
   页面，下载最新版本里的 `browser-copilot-<版本>.zip`。
2. 解压到一个会长期保留的文件夹（扩展会从这个文件夹加载）。
3. 打开 `chrome://extensions`。
4. 打开右上角的**开发者模式**。
5. 点击**加载已解压的扩展程序**，选择解压出来的文件夹——即包含
   `manifest.json` 的那一层。
6. 点击工具栏上的扩展图标，打开侧边栏。

### 方式二：从源码构建

需要 **Node.js 20+**。

```bash
git clone git@github.com:dcc123456/browser-copilot.git
cd browser-copilot
pnpm install
pnpm run build
```

然后加载到 Chrome：

1. 打开 `chrome://extensions`。
2. 打开右上角的**开发者模式**。
3. 点击**加载已解压的扩展程序**，选择构建出来的 **`dist/`** 目录。
4. 点击工具栏上的扩展图标，打开侧边栏。

习惯用 npm 的话，`npm install && npm run build` 同样可以。

运行 `pnpm package`（或 `npm run package`）会在构建之外额外生成
`releases/browser-copilot-<版本>.zip`，也就是发布流程挂到 GitHub Releases 上的
同一个可加载压缩包；为减小体积，压缩包不包含 source map。

### 更新

```bash
git pull
pnpm install
pnpm run build
```

然后在 `chrome://extensions` 的扩展卡片上点**重新加载**。仅重新构建不会刷新已加载的
service worker。

## 支持哪些模型

任何遵循 OpenAI chat-completions 协议的端点。扩展内部**没有任何厂商专属代码**——一个
provider 只是配置，不是一条代码分支——所以下面没列出的端点同样能用，只要它接受
`POST {baseUrl}/chat/completions`、`Bearer` 认证和 SSE 流式返回。

下列预设只是帮你省去输入 URL，每个字段都可以改。

| 预设 | 接口地址（Base URL） | 模型示例 |
| --- | --- | --- |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat`、`deepseek-reasoner` |
| 火山方舟 Volcengine Ark | `https://ark.cn-beijing.volces.com/api/v3` | `doubao-seed-code`，或接入点 ID `ep-…` |
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| OpenRouter | `https://openrouter.ai/api/v1` | `deepseek/deepseek-chat` |
| Moonshot / Kimi | `https://api.moonshot.cn/v1` | `kimi-k2-0905-preview` |
| 阿里云百炼 DashScope | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` |
| 硅基流动 SiliconFlow | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` |
| Ollama（本地） | `http://localhost:11434/v1` | `qwen3:8b` |
| LM Studio（本地） | `http://localhost:1234/v1` | `local-model` |
| 自定义 | — | 任意 OpenAI 兼容端点 |

### 怎么选模型

**关键是支持 function calling（工具调用）。** 助手是通过调用工具来读取和操作页面的，所以
不支持工具调用的模型可以正常聊天，但永远不会主动读页面或动手。此时手动勾选"附带当前页面"
仍然有效——弱一些的模型依然可用，只是不够省事。

- **日常使用** —— `deepseek-chat`、`gpt-4o-mini`、`qwen-plus`：快且便宜。
- **代码评审、复杂推理** —— `deepseek-reasoner`、`doubao-seed-code`。
- **长页面与长任务** —— 优先选上下文窗口大的模型；页面文本上限约 12,000 字符，多步任务
  还会保留自身的操作历史。
- **本地 / 隐私优先** —— Ollama 或 LM Studio，页面内容完全不出本机。请选支持工具调用的
  模型（例如较新的 Qwen），并接受响应更慢。

## 如何配置模型

打开侧边栏 → **设置** → **添加模型服务**。

1. **选一个预设。** 接口地址和建议模型会自动填好。
2. **粘贴 API 密钥。** 到对应平台获取：
   [DeepSeek](https://platform.deepseek.com/api_keys) ·
   [火山方舟](https://console.volcengine.com/ark) ·
   [OpenAI](https://platform.openai.com/api-keys) ·
   [OpenRouter](https://openrouter.ai/keys) ·
   [Moonshot](https://platform.moonshot.cn/console/api-keys) ·
   [百炼](https://bailian.console.aliyun.com/) ·
   [硅基流动](https://cloud.siliconflow.cn/account/ak)。
   本地 Ollama 或 LM Studio 填任意非空字符串即可。
3. **填模型。** 手动输入，或点**获取模型列表**让端点返回可用模型。不是所有网关都实现了
   `/models`，所以手动输入永远有效。
4. **点"测试连接"。** 它会发一次真实请求，同时验证**密钥和模型**是否都可用。
5. **保存。**

### 各字段说明

| 字段 | 说明 |
| --- | --- |
| **名称** | 你自己给这份配置起的名字，例如"方舟 coding plan"。 |
| **接口地址** | 到 `/chat/completions` **之前**为止的部分。保留版本段（`/v1`、`/api/v3`）——各厂商不一致；粘贴完整地址会被自动裁剪。 |
| **API 密钥** | 以 `Authorization: Bearer …` 发送。 |
| **模型** | 模型 ID；方舟上也可以填专用接入点 ID（`ep-…`）。 |
| **温度** | 可选，留空则用服务端默认值。 |
| **最大 token 数** | 可选的回复长度上限，留空由服务端决定。 |
| **额外请求头（JSON）** | 可选，供需要归属或路由头的网关使用。 |

### 配置多个服务

可以添加任意多个，用**使用这个**切换——评审用强模型、总结用便宜的、涉及敏感内容时用本地
的。凭据按配置分别保存，切换不需要重新输入密钥。

### 每条回复最多操作步数

设置里可以限制代理在一轮中最多执行多少个动作（读取、点击、滚动、填写等），超过后会停止以防
死循环。默认是 **20**，可调范围 1–100。碰到上限并不代表任务丢失——发一句"继续"就能从停下
的地方接着做。

### 密钥存在哪

存在 `chrome.storage.local`，**仅本机**。刻意没有用 `storage.sync`——那会把密钥同步到你
登录过的每一个浏览器。

它**没有加密**：任何能读取你浏览器配置目录的人都能读到。对于没有主密码机制的扩展，这是常态
——如果某个密钥不能接受这种风险，请改用本地模型。

## 使用说明

### 对话

输入后按 **Enter** 发送（**Shift+Enter** 换行）。使用中文/日文/韩文输入法时，第一次回车
确认候选词、第二次才发送，不会打断组词。

标签栏下方的工具条，左侧是**附带当前页面**，右侧是**历史**按钮。输入区可以拖动顶部边缘调整
高度，高度会被记住。

当对话已有内容时，发送按钮旁会出现**＋ 新对话**。可以随时关闭侧边栏：回答会在后台继续，
重新打开时恢复对话记录，并接回仍在进行中的回复。

回复以 Markdown 渲染——标题、列表、表格，代码块带复制按钮；而**你自己输入的内容**保持原样。
中文标点遵守避头尾规则（句尾的 `？`、`。` 不会被单独挤到下一行）。

### 读取与操作页面的两条路径

- **你主动附带。** 勾选"附带当前页面"，不会弹确认——你已经指明了是哪一页、什么时候。在这
  条消息的后续处理中，助手可以不再询问就重新读取该页面。
- **助手主动请求。** 对于你**没有**附带的页面，模型发起的动作——半自动下的一次读取，或任意
  点击/输入——会先弹确认（全自动下除外）。

当前标签页可能是邮箱、内部系统或银行账单。你主动附带是明确同意；模型自己决定则不是，这就是
半自动逐步确认的原因。附带带来的免确认**仅限那一个页面**，按 origin 和路径比对（忽略 query
string 和 `#fragment`）。回答中切到别的页面，新页面会重新询问。

**设置 → 页面读取权限 → 检测当前标签页**可以在依赖它之前先告诉你这个页面能不能读。

### 界面语言

**设置 → 语言**：English、简体中文，或**自动**（跟随浏览器）。面板语言与 Chrome 自身的界面
语言无关。

### 外观主题

面板**跟随操作系统**的浅色/深色主题，切换系统主题后立即生效，无需刷新。两套主题都由测试
套件按 WCAG AA 标准（4.5:1）校验对比度。

## 已保存的资料与密码

**数据**标签保存了允许代理替你填写的内容：

- **资料** —— 姓名、邮箱、电话、地址及自定义字段。表单需要时，调用 `get_my_profile` 查看
  可用内容，再逐个填写。
- **密码** —— 按标签、网址、用户名保存。代理只能按标签列出条目；要用时调用 `get_secret`，
  它会**把密码直接填进目标字段，绝不把值返回给模型**。每次使用更新使用计数；条目可重命名、
  删除。
- **操作历史** —— 每个动作（点击、填写、滚动、跳转、切换标签）都带时间戳和站点记录，并标记
  是已确认、自动执行还是被拒绝。可单条删除或全部清空。

已保存内容存在本机 `chrome.storage.local`，不会同步，也**绝不会**发给模型。密码在静态存储
时未加密——参见[密钥存储](#密钥存在哪)。

## 对话历史

聊天工具条上的时钟图标会从左侧打开历史抽屉，列出过去的对话。每行显示标题（第一条用户消息）、
相对时间和消息数。你可以：

- **继续对话** —— 点击该行；完整记录（包括操作 chip）会被还原，模型也能看到之前的上下文。
- **预览** —— 用眼睛图标就地查看。
- **重命名** —— 行内编辑。
- **删除**。

对话持久化在 `chrome.storage.local`（浏览器重启后仍在，每条保留最新 200 条消息）。抽屉里或
发送按钮旁的**＋ 新对话**可以开始新的会话。

## 技能（Skills）

技能就是一段存下来的指令包——把提示词里**不变**的那部分固定下来。

**技能 → 新建技能**，填名称、一句话说明适用场景、以及具体指令。然后二选一：

- 在输入框打 **`/`** 手动选择，或
- 保持"允许 agent 自动应用"开启，当你的消息与说明相符时它会自行使用。

适合存代码评审清单、固定的总结格式、翻译术语表或数据提取的字段结构。

前期只把名称和说明提供给模型，完整指令按需加载——十个技能不会让每次请求都背上十份指令正文。

## 隐私与权限

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存设置、模型服务、技能、对话、资料和凭据。 |
| `tabs` | 知道当前是哪个标签页、读取其标题/URL，并在你要求时打开/切换/关闭标签。 |
| `scripting` | 注入页面内核以读取或操作当前标签页。 |
| `sidePanel` | 显示侧边栏。 |
| `http(s)` 的 `host_permissions` | 读取和操作页面，以及请求你配置的模型端点。 |

**特意没有**：`alarms`（不做任何定时任务），以及常驻 content script——在某轮回答需要之前，
不会向任何页面注入内容。

**会离开你电脑的数据**：你的消息，以及你附带或批准读取的页面文字，发往**你自己配置的**模型
端点。保存的密码在本地填写，**绝不会**包含在任何请求里。没有埋点、没有统计分析，本项目不
存在任何服务器。

**对话记录**持久化在 `chrome.storage.local`，方便日后续聊；每条会话保留最新 200 条消息。
你可以从历史抽屉删除任一会话，或在 `chrome://extensions` 里清除整个扩展的存储。

## 开发

```bash
pnpm run dev         # 改动即重新构建
pnpm run typecheck   # tsc --noEmit
pnpm run test        # vitest
pnpm run build       # 生产构建输出到 dist/
pnpm run package     # 构建并生成 releases/browser-copilot-<版本>.zip
pnpm run icons       # 重新生成 public/icons
```

推送 tag 或在 GitHub 上发布 Release 时，会运行
`.github/workflows/release.yml`：执行类型检查、测试、构建，并把同一个可加载的
zip 附加到该 Release。

改动 service worker 后，需在 `chrome://extensions` 点**重新加载**。

```
src/
  background/
    index.ts      Service worker：命令通道 + 流式 agent 端口
    agent.ts      工具定义、工具调用循环、模式与确认门控
    driver.ts     标签/框架执行驱动、导航与标签管理
    page.ts       通过一次性脚本注入读取当前标签页
    keepalive.ts  引用计数的 worker 保活，覆盖进行中的回答
  inpage/
    kernel.ts     自包含的页内操作执行器（点击、填写、滚动、快照）
  lib/
    llm.ts        OpenAI 兼容的流式客户端 + SSE 累加器
    providers.ts  模型服务配置、预设、校验
    storage.ts    chrome.storage 访问：设置、技能、对话、数据
    ops.ts        driver 与 kernel 共享的 Op/Target/PageSnapshot 类型
    messages.ts   面板 ↔ worker 的通信协议
    pages.ts      判定哪些 URL 允许读取、同页比对
    extract.ts    空白折叠与长度截断
    skills.ts     技能校验与提示词组装
    slash.ts      输入框斜杠命令解析
    markdown.ts   Markdown 解析器，输出类型化语法树（不产生 HTML）
    i18n.ts       文案词典
  sidepanel/      React 界面：对话、技能、数据、设置
```

改代码前值得知道的几个设计决定：

**Markdown 解析成语法树，绝不生成 HTML。** 助手的输出是**不可信输入**（模型可能刚读过被攻击
者控制的页面），而侧边栏是**特权环境**（这里的脚本能访问存放密钥的 `chrome.storage`）。因此
全程不拼接 HTML 字符串，代码中不存在 `dangerouslySetInnerHTML`——注入在结构上就不可能。链接
目标按协议**白名单**校验。

**页内内核是自包含的。** 它通过 `chrome.scripting.executeScript({ func, args })` 序列化注入，
因此不能引用模块级状态，所有辅助函数都在函数内部。driver 会向所有框架注入、对结果排序，并从
导航导致的上下文丢失中恢复。

**所有需要持久化的数据都在 `chrome.storage`。** MV3 的 service worker 空闲约 30 秒就会被回收，
模块级变量会一起消失。每次回答还持有引用计数的保活——因为关闭侧边栏会销毁让 worker 保持唤醒
的端口，而回答途中关闭面板是被支持的操作。代理模式和步数上限按轮次（并按每个动作）读取，所以
改设置无需重新加载。

## 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 提示未配置模型服务 | 设置 → 添加模型服务。 |
| 401 / 403 | 密钥错误或已过期，或密钥与接口地址不属于同一家厂商。 |
| 发送时 404 | 接口地址少了版本段（`/v1`、`/api/v3`），或模型名不存在。点**测试连接**快速定位。 |
| 提示无法读取此页面 | 这是 `chrome://`、`file://`、应用商店或其他扩展的页面，任何权限都无法解决。 |
| 全自动下仍然弹确认 | 在 `chrome://extensions` 重新加载扩展，再确认下拉框显示 ⚡ 全自动；模式在每个动作前都会读取。 |
| 提示"Stopped after N tool rounds" | 达到了步数上限。发一句"继续"，或在设置里调高**每条回复最多操作步数**。 |
| 页面文字为空或不全 | 内容在 iframe 里、读取之后才渲染，或藏在"加载更多"后面。刷新重试，先选中你关心的部分。 |
| 助手能聊天但从不读页面或动手 | 模型不支持 function calling。改为手动勾选"附带当前页面"，或换模型。 |
| 长页面像是被截断了 | 确实被截断：上限约 12,000 字符，请先选中关键段落。 |
| 点工具栏图标没反应 | 在 `chrome://extensions` 重新加载扩展，可能是 worker 启动失败。 |
| 本地模型拒绝请求 | 确认本地服务已启动，且接口地址以 `/v1` 结尾。 |

## 已知限制

- 一次聚焦一个标签页。动作可以定位到具体框架，但大范围页面读取看到的仍是已渲染的 DOM。
- 页面文本上限约 12,000 字符；截断这件事会告知模型，所以它会说明而不是自己编。
- 工具调用在达到配置的步数上限（默认 20）后停止，以防模型陷入循环。
- 让模型自主读取和操作需要支持 function calling 的模型。
- 端点必须接受来自浏览器扩展的请求。公开 API 都可以；对来源检查严格的内网网关可能不行。
- 保存的密码在静态存储时未加密；如果某个密钥或凭据不能留在浏览器配置目录里，请改用本地模型。
