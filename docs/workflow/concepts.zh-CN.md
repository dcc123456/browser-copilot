# 工作流概念

这些概念适用于所有算子。先读一遍，再看单个算子页会更容易理解。

## 工作流结构

工作流是一张有向图：

- **触发器** — 入口。它保存工作流名称、一个或多个启动配置、声明的输入参数，以及运行设置。
- **步骤** — 画布上的算子。每一步读取变量与页面状态，执行一个动作，通常写出一个结果。
- **连线** — 告诉引擎下一步执行谁。命名端口用来表达分支、回退与循环返回。

运行时从触发器开始沿连线执行，直到没有可走的出边或某一步结束了整张图。每次运行都有一份全新的**变量表**：先写入声明的输入，之后每个步骤在执行时新增或覆盖变量。后续步骤能看到之前所有步骤产出的值。

属性面板有两个作用域：

- 选中 **触发器** 算子，编辑工作流名称、描述、触发器，以及保存日志、完成通知等运行设置。
- 选中其他算子，编辑该算子的设置、输出变量、错误策略与目标契约。

## 变量与插值

变量是步骤之间唯一的数据通道。

- 会产出结果的步骤都有 **输出变量名** 字段。按数据本身命名，而不是按算子命名。
- 任何支持模板的文本字段都能用 `{{name}}` 读取变量。
- 后面的步骤可以覆盖同名变量；再往后的步骤看到的是最新值。

### 引用语法

| 写法               | 读取的内容                     |
| ------------------ | ------------------------------ |
| `{{headline}}`     | 顶层变量。                     |
| `{{user.email}}`   | 对象的属性。                   |
| `{{rows[0].name}}` | 先按下标取数组元素，再取属性。 |
| `{{map["key"]}}`   | 名称里含点号或空格的属性。     |
| `{{rows[0]}}`      | 该位置上的整个对象。           |

引用允许在 token 内出现空格。格式错误的表达式会原样保留，与引用一个不存在的变量表现相同。

### 以文本保存的对象

模型输出和部分页面读取结果是字符串。当引用在这种字符串上继续取属性或下标时（例如 `article` 保存的是 `{"title": "…"}`，而模板写的是 `{{article.title}}`），引擎会先把字符串按 JSON 解析，包括自动去掉外层 ` ```json ` 代码围栏。因此同一份 AI 回答既可以整体读取（`{{article}}`），也可以逐字段读取（`{{article.title}}`），不需要改变它的存储方式。

### 插值的作用范围

算子参数包中的每个字符串都会被插值，包括嵌套对象与数组：条件比较值、嵌套的元素定位、由循环变量拼出的选择器、文件名。**JavaScript 代码** 的 `code` 参数还会额外做 JavaScript 字符串字面量转义，值里的引号或换行不会破坏脚本。

非文本设置不参与插值：下拉选项、复选框、数字边界以及输出变量名本身。这些位置需要通过算子自己的字段来接收数据。

### 缺失与空值

- token 解析不到任何值时，会**原样留在文本里**，而不是替换成空字符串。
- 引擎会记录本次运行中残留的 token。那些绝不能把字面量 `{{name}}` 输入页面的动作步骤会直接让该步失败，并报“未解析输入”错误。
- token 解析成空字符串时，步骤看到的确实是空值。会因此清空表单字段或用空值覆盖数据的算子会识别这种情况并拒绝或报告。

这个区分是有意设计的：`{{missing}}` 代表工作流本身有问题，而 `{{optionalNote}}` 解析成 `""` 是合法的空值。

### 运行时变量

有些变量由引擎提供，而不是由某个算子写出：

| 变量                  | 可用位置         | 值                              |
| --------------------- | ---------------- | ------------------------------- |
| `loopIndex`           | 循环体           | 从 0 开始的迭代序号。           |
| `loopItem`            | 数据循环         | 当前数组项。                    |
| `loopElementSelector` | 元素循环         | 指向当前匹配元素的 CSS 选择器。 |
| `dataTable`           | 整次运行         | 本次运行的行对象数组。          |
| `lastExport`          | **导出数据**之后 | 已导出的文本内容。              |
| `lastExportPath`      | 导出成功之后     | 实际写入的文件名。              |

各算子页还会列出自己的输出变量与回退变量名。

## 数据表

`dataTable` 是运行期间的行对象数组，相当于工作流的电子表格。**导出数据** 选择导出 **Table** 时，读取的就是它。

- [获取文本](operators-interaction.zh-CN.md#operator-get-text)、[读取页面](operators-browser.zh-CN.md#operator-read-page) 等读取算子可以把读到的内容写进数据表：勾选 **保存到数据表**，填写 **数据列**，每个匹配结果就成为该列的一个单元格。
- 在循环内，一次迭代写入 `loopIndex` 对应的那一行；不在循环内时，多个匹配结果会各占一行。
- 再次写入同一列是替换单元格，因此两次读取可以拼出两列表格，而不是把行数翻倍。
- [插入数据](operators-data.zh-CN.md#operator-insert-data)、[删除数据](operators-data.zh-CN.md#operator-delete-data)、[排序数据](operators-data.zh-CN.md#operator-sort-data) 等数据算子编辑的是同一张表。
- 数据表最多保存 100,000 行；超出后的写入会被忽略并报告。

空表无法导出：**导出数据** 会明确报错，而不是写出一个空文件。如果只需要一个值，请改成导出 **Variable（变量）**。

## 端口、分支与循环

大多数算子只有一个输出，直接连到下一步。额外端口让一个节点可以选择不同路径：

- **[条件判断](operators-conditions.zh-CN.md#operator-conditions)** — 按顺序排列的多条路径，各有自己的输出。运行走第一条所有条件都匹配的路径；**fallback** 输出始终存在，在没有路径匹配时使用。
- **[元素是否存在](operators-conditions.zh-CN.md#operator-element-exists)** — 元素存在时走一个输出，不存在时走另一个。
- **错误回退** — 当某一步的 **出错时** 策略是“执行回退分支”时，失败路径走额外的 fallback 端口。
- **循环** — 循环体从循环节点连出，通过 loop-back 端口回到循环节点，然后重复。

循环会提供上面列出的运行时变量：

- **[重复任务](operators-conditions.zh-CN.md#operator-repeat-task)** 按固定次数重复循环体。
- **[While 循环](operators-conditions.zh-CN.md#operator-while-loop)** 在条件成立时重复，最多 1,000 次。
- **[循环数据](operators-conditions.zh-CN.md#operator-loop-data)** 遍历 JSON 数组（`loopItem`、`loopIndex`）。
- **[循环元素](operators-conditions.zh-CN.md#operator-loop-elements)** 遍历页面元素（`loopElementSelector`、`loopIndex`）。
- **[循环断点](operators-conditions.zh-CN.md#operator-loop-breakpoint)** 结束当前循环，继续执行循环之后的步骤。

把分支连回更早的算子会让那个算子重复执行。编辑器会提示这种回跳形状；请确保条件最终会改变，否则运行会在迭代上限处停止。

## 错误、重试与可靠性

算子抛错时，默认会让整次运行失败。属性面板为每个算子提供这些控制：

| 设置                  | 作用                                          |
| --------------------- | --------------------------------------------- |
| **禁用算子**          | 跳过该步骤（包括副作用），但不删除它。        |
| **超时**              | 运行超过限制时让该步失败。填 `0` 表示不限制。 |
| **出错时 → 重试**     | 按配置的间隔重试动作，并指定次数。            |
| **出错时 → 抛出错误** | 用指定消息让运行失败。                        |
| **出错时 → 继续执行** | 把该步标记为失败，然后继续执行下一步。        |
| **出错时 → 回退分支** | 沿该节点的 fallback 连线继续。                |

运行级行为：

- 开始前引擎会检查必填参数。缺失值会写入运行日志，运行在第一个无法工作的算子前停止，而不是执行到一半才失败且没有上下文。
- 失败的运行会保留日志。点击日志行可在画布上定位对应算子。
- **调试模式** 会在带断点的算子前暂停，显示该处捕获的变量，并支持继续、单步与停止。
- **从此处运行** 从选中的节点开始执行，而不是从触发器开始，并使用当前页面状态。
- 工作流卡片上的 **继续运行** 会从最后一个干净完成的步骤之后继续，已经执行过的登录或提交不会重复。
- **保存执行日志** 把运行记录留在历史中；**完成时通知** 在运行结束时发送通知。

### 目标与校验

工作流可以带一个 **工作流目标**：一句摘要，加上最后一步之后要检查的成功条件。生成的工作流还会给单个步骤写入目标契约——这一步要达成什么，以及哪些可观察事实可以证明它。

这些契约用于：

- **认证** — 从执行、逐步契约到工作流目标的分级校验。修改契约或图之后，工作流会回到未认证状态，直到重新校验通过。
- **AI 修复** — 运行失败后，修复智能体依据目标契约与失败信息修改节点，并报告工作流能否在没有 AI 参与的情况下成功。
- **AI 接管** — 可选地在真实页面上完成一次失败的步骤，修复建议以待确认状态保留，不会静默写入。

手工搭建的工作流可以不写目标契约。它让“成功”成为可检查的事实，而不是“运行没有抛错”。

### AI 种子召回

生成工作流时，曾解决过类似目标的已认证工作流可以作为步骤证据提供给生成器。种子只提供步骤建议；生成出来的图仍然要像其他工作流一样保存并执行。

## 文件、下载与上传

### 文件写到哪里

扩展按以下顺序决定目标位置：

1. **已配置的下载目录** — 在 设置 → 下载目录 中选择。文件会静默写入。
2. **保存对话框** — 未配置目录且侧边栏打开时，由你选择位置。
3. **扩展内部目录** — 无人值守运行没人能点对话框时，文件写入扩展存储中的 `browser-copilot-downloads/`，运行日志会给出文件名。

会产出文件的算子都走这条链：**导出数据**、**截图**（勾选保存到电脑时）、**保存到本地** 等。**处理下载** 会等待浏览器下载，并可通过同一路径保存文件。

算子接受文件路径时，路径是**相对于下载目录**的，不是宿主机绝对路径。允许子目录（`reports/sales.xlsx`），路径中的 `{{变量}}` 会在运行时插值。

### 上传来源

[上传文件](operators-interaction.zh-CN.md#operator-upload-file) 支持四种来源：

| 来源               | 适用场景                                        |
| ------------------ | ----------------------------------------------- |
| 用户选择文件       | 运行时有人在旁边选择文件。                      |
| 来自前面步骤的文件 | 变量里已经保存了 data URL、文件产物或产物数组。 |
| 最新下载的文件     | 按文件名模式与类型过滤，上传最新的下载文件。    |
| 指定文件路径       | 上传下载目录中某个具体文件。                    |

### 电子表格

[解析 Excel](operators-data.zh-CN.md#operator-parse-excel) 从用户选择的文件、前面步骤保存在变量里的文件，或下载目录中的相对路径读取 `.xlsx` / `.csv`。存在表头行时会产出按列名索引的对象数组，同时保留原始二维数组。

## 凭证

[获取凭证](operators-data.zh-CN.md#operator-get-secret) 在运行时把已保存的凭据字段读入变量。凭据保存在扩展的凭据库中（数据 → 密码与账号），不会写进工作流 JSON，并且每次运行都会重新读取。

它只适合必须保密的值：密码、API key、token。用户名或搜索关键词不需要这个算子——放进表单值或触发器输入参数即可，保持可见、可编辑。

读取的是字段引用，因此在数据页更新密码后，下一次运行就会生效，不需要修改工作流。

## AI 能力

Browser Copilot 在多个位置使用 AI。这些能力彼此独立，运行工作流并不依赖它们。

| 能力         | 出现位置                 | 作用                                                                           |
| ------------ | ------------------------ | ------------------------------------------------------------------------------ |
| **AI Agent** | 通用分类中的算子         | 读取页面或元素，按你的提示分析，可选择在页面上操作，并把文本答案存入变量。     |
| **AI 接管**  | 设置；失败运行（启用时） | 让智能体在真实页面上完成一次失败步骤，修复建议以待确认状态提供，不会静默应用。 |
| **AI 修复**  | 运行结果与工作流工具栏   | 根据运行日志与目标契约诊断失败，修改图并验证结果。                             |
| **目标契约** | 触发器与每个算子的面板   | 定义可供校验与修复使用的成功事实。                                             |
| **种子召回** | 工作流生成               | 把之前认证通过的工作流作为步骤证据提供给生成器。                               |
| **OCR**      | OCR 算子                 | 使用 Tesseract.js 在本地识别文字，不发起网络请求。                             |

调用模型的 AI 能力使用设置中配置的提供方，并各自带有预算或轮数上限，单个步骤不会无限循环。模型调用失败时，AI Agent 步骤会像其他步骤一样报错，由它的 **出错时** 策略决定后续行为。

## 触发器与定时任务

一个工作流可以配置多个触发器。第一个是**主触发器**，会同步到工作流记录上，供列表与调度器显示工作流的启动方式。禁用一个触发器不会影响其他触发器。

各类触发器的细节：

- **手动** 工作流从编辑器、工作流标签页，或右键菜单/快捷键触发器启动。
- **时间类** 触发器（间隔、指定日期、每周的某几天）注册为浏览器闹钟，浏览器运行期间到点触发。
- **页面类** 触发器（访问网页时、元素变化时）由注入页面的观察器实现，按网址或选择器匹配。
- **浏览器类** 触发器（浏览器启动时、键盘快捷键、右键菜单）由扩展自身注册。

**定时任务** 是另一个入口：任务拥有自己的调度配置，可以用自己的变量载荷运行一个已保存的工作流。启动逻辑属于工作流本身时用触发器；多个任务共享同一套调度，或任务之间需要串联时，用定时任务。

## OCR 构建变体

Browser Copilot 有两种构建变体：

- **完整版** — 包含 Tesseract.js 与语言数据，[OCR 文字识别](operators-browser.zh-CN.md#operator-ocr) 可离线工作。
- **精简版**（`no-ocr`）— 移除 OCR 引擎与语言文件。OCR 算子显示为不可用，并拒绝运行。

其他功能在两种构建中行为一致。OCR 算子页带有 **仅完整版可用** 徽章。
