# 条件控制算子

本页介绍决定运行走向和重复次数的算子：**条件**、**元素是否存在**、四种循环，以及提前结束循环的算子。每个算子都列出设置、输出以及 Browser Copilot 特有的行为。分支端口与回跳连接在[工作流概念](concepts.zh-CN.md#端口分支与循环)中统一说明，步骤失败后的处理见[错误、重试与可靠性](concepts.zh-CN.md#错误重试与可靠性)；通用的**描述**、**禁用算子**、**超时**和**出错时**设置适用于整个节点，因此不在表格中重复。定位器支持 CSS 选择器或 XPath 表达式，数据字段支持 `{{variables}}`。

<!-- operator:repeat-task -->

## 重复任务

按固定次数运行所连接的分支，然后从 **end** 输出继续。[Automa 参考](https://www.goautoma.com/extension/docs/blocks/repeat-task.html)

### 设置

| 字段     | 类型 | 默认值 | 说明                                                               |
| -------- | ---- | ------ | ------------------------------------------------------------------ |
| 重复次数 | 数字 | `1`    | 分支执行的次数。填 `0` 时循环体一次也不执行，直接从 **end** 继续。 |

### 输出

- `loopIndex` —— 从 0 开始的重复序号，每轮执行前写入，结束后保留最后一轮的值。
- **loop**（`output-1`）进入循环体；**end**（`output-2`）在最后一轮结束后继续。

### Browser Copilot 说明

- 循环体通过把最后一步连回本节点来收尾；再次到达循环节点即表示一轮结束，详见[端口、分支与循环](concepts.zh-CN.md#端口分支与循环)。
- 填 `0` 时循环体不执行，但 **end** 分支照常运行。
- 不提供 `loopItem`，重复序号是这里唯一的循环上下文。
- 循环体内某一步失败会同时终止循环与运行，**end** 分支不会执行，见[错误、重试与可靠性](concepts.zh-CN.md#错误重试与可靠性)。

<!-- operator:conditions -->

## 条件

自上而下依次判断命名的输出路径，运行走第一条所有条件都成立的路径；都不成立时走 **fallback**。[Automa 参考](https://www.goautoma.com/extension/docs/blocks/conditions.html)

### 设置

| 字段             | 类型   | 默认值   | 说明                                                                                               |
| ---------------- | ------ | -------- | -------------------------------------------------------------------------------------------------- |
| 输出路径         | 列表   | 无       | 有序的分支列表。每条路径拥有一个输出端口和独立的条件树，最多 20 条；达到上限后**添加路径**不可用。 |
| 路径名称         | 文本   | `Path N` | 显示在该路径端口和运行日志中的名称。改名不会改变路径 id，已有连线不受影响。                        |
| 路径条件         | 条件树 | 空       | OR 组套 AND 行：同组内每一行都成立，且至少一个组成立，该路径才算命中。没有任何行的路径永不命中。   |
| 无条件满足时重试 | 复选框 | 关闭     | 随算子保存；当前构建不会重新判断（见说明）。                                                       |
| 次数             | 数字   | `10`     | 仅在开启**无条件满足时重试**时显示。                                                               |
| 超时（毫秒）     | 数字   | `1000`   | 仅在开启**无条件满足时重试**时显示。                                                               |

### 输出

- 每条配置好的路径一个端口，key 为 `output-<pathId>`，标签是路径名称；另有始终存在的 **fallback** 端口（`output-none`）。
- 不写入变量；运行日志会写明命中的路径，或提示全部不成立。

### Browser Copilot 说明

- 只有第一条命中的路径会执行。调整判断顺序请用路径的上移 / 下移按钮，不要复制条件。
- 空路径会被跳过，而不是当作恒真，所以配了一半的分支不会吞掉整次运行。
- 端口互斥：路径命中但对应端口没有连线时，运行在该节点结束，不会落到其他路径，详见[端口、分支与循环](concepts.zh-CN.md#端口分支与循环)。
- 导入的工作流可能带旧的 `code` 表达式；它的优先级高于 `paths`，此时节点使用 `output-1`（真）与 `output-2`（假）。编辑器写入的是 `paths`，只要该键存在就以它为准——包括空列表，那会把每次运行都送到 **fallback**。
- **无条件满足时重试**及其中两个数字只为往返保存，当前引擎不会应用。可行替代是在节点前加一个**延时**步骤，或用页面条件驱动的 **While 循环**。
- 条件行可以用运算符比较两侧的值（`Equals`、`Contains`、大小比较、正则等），也可以是独立判断：元素存在 / 不存在 / 可见、数据存在、代码片段。插值之后，元素判断在当前页面上执行。

<!-- operator:element-exists -->

## 元素是否存在

定位器至少匹配到一个元素时走 **exists** 端口，一个都没有时走 **not exists** 端口。[Automa 参考](https://www.goautoma.com/extension/docs/blocks/element-exists.html)

### 设置

| 字段               | 类型     | 默认值        | 说明                                                       |
| ------------------ | -------- | ------------- | ---------------------------------------------------------- |
| 查找元素方式       | 下拉选择 | `cssSelector` | `cssSelector`、`xpath` 或 `text`。XPath 由取值本身识别。   |
| 选择器             | 文本     | —             | 要探测的定位器，支持 `{{variables}}`。                     |
| 选择多个元素       | 复选框   | 关闭          | 通用定位选项；本判断本来就是“一个或多个”，此项不改变行为。 |
| 等待选择器         | 复选框   | 关闭          | 由通用定位选项保存；当前构建只探测一次（见说明）。         |
| 选择器超时（毫秒） | 数字     | `5000`        | 仅在开启**等待选择器**时显示。                             |
| Try for            | 数字     | `1`           | 表单记录的重试次数。                                       |
| 超时（毫秒）       | 数字     | `500`         | 表单记录的重试间隔。                                       |
| 不存在时抛出错误   | 复选框   | 关闭          | 记录意图：不存在时让步骤失败，而不是走 **not exists**。    |

### 输出

- **exists**（`output-1`）与 **not exists**（`output-2`），两者互斥；端口未连线时运行在该节点结束。
- 不写入变量，匹配数量只出现在运行日志里。

### Browser Copilot 说明

- 引擎只探测一次。**Try for**、**超时（毫秒）**、**等待选择器**和**不存在时抛出错误**会随算子保存，但这里都不会被读取，所以元素出现较晚时仍然会走 **not exists**，即使勾选了抛出错误。请在本节点前加一个**延时**步骤，或在真正需要元素的那一步里等待。
- 判断标准是“匹配数量大于 0”：隐藏元素同样计入，定位器也不需要唯一。
- **查找元素方式 → text** 会被保存，但不会转成文本搜索，取值仍按选择器查询。这里请用 CSS 或 XPath，或在**条件**里用**元素文本**条件行。
- 无论结果如何都要继续时，把两个端口都连上；留空的一侧会让运行在对应的判断结果处结束。

## While 循环

在条件成立期间重复运行所连接的分支，每轮开始前先判断条件。[Automa 参考](https://www.goautoma.com/extension/docs/blocks/while-loop.html)

### 设置

| 字段           | 类型   | 默认值 | 说明                                                         |
| -------------- | ------ | ------ | ------------------------------------------------------------ |
| While 循环条件 | 条件树 | 未设置 | OR 组套 AND 行，构建方式与**条件**算子相同。每轮开始前判断。 |

### 输出

- `loopIndex` —— 循环体内从 0 开始的轮次序号。
- **loop**（`output-1`）运行循环体；**end**（`output-2`）在条件不再成立后继续。

### Browser Copilot 说明

- 第一次判断就不成立时循环体一次也不执行，运行直接从 **end** 继续。
- 循环最多 1,000 轮。超过上限时运行以迭代超限错误失败，而不是一直空转；该节点记为失败，**end** 不会执行。
- 没有保存条件的节点会记录一条错误并执行 0 轮。编辑器默认给出一组包含两个空行的 OR 组，但这些行只有在你编辑条件树后才会写入节点；而空值与空值比较是成立的，原样保存的默认条件会让循环跑到上限，请填入真实操作数。
- **结束循环**从 **end** 离开。只跳过当前项的循环断点同样消耗一轮，因此“总是跳过”的循环体绕不过上限保护。
- 循环体内某一步失败会终止循环与运行，不经过 **end**，见[错误、重试与可靠性](concepts.zh-CN.md#错误重试与可靠性)。
- 导入的工作流可能用 `code` 表达式代替条件树。已保存的条件树优先，只有没有条件树时才使用表达式。

## 循环数据

遍历数据表、数字区间、变量、JSON 数组或页面元素列表，把当前项写入 `loopItem`，把位置写入 `loopIndex`。[Automa 参考](https://www.goautoma.com/extension/docs/blocks/loop-data.html)

### 设置

| 字段                       | 类型     | 默认值         | 说明                                                                                          |
| -------------------------- | -------- | -------------- | --------------------------------------------------------------------------------------------- |
| 循环 ID                    | 文本     | 自动（6 位）   | 供**循环断点**定位本循环，也用于记录恢复进度。                                                |
| 循环遍历                   | 下拉选择 | `data-columns` | `data-columns`（数据表）、`numbers`、`google-sheets`、`variable`、`custom-data`、`elements`。 |
| 引用键                     | 文本     | —              | 仅 Google 表格来源使用；当前构建不可用，见说明。                                              |
| 变量名                     | 文本     | —              | 仅变量来源使用。`order.items` 这类点路径与 `{{order.items}}` 读法一致。                       |
| 元素选择器                 | 文本     | —              | 仅页面元素来源使用，支持 CSS 或 XPath；每个匹配项都会遍历。                                   |
| 等待选择器                 | 复选框   | 关闭           | 仅页面元素来源：轮询直到至少出现一个匹配项。                                                  |
| 选择器超时（毫秒）         | 数字     | `5000`         | 仅页面元素来源；开启**等待选择器**时显示。                                                    |
| 自定义数据（JSON 数组）    | 文本     | `[]`           | JSON 来源。**导入文件**还接受不超过 1MB 的 `.json`、`.csv` 与 `.xlsx`。                       |
| 首行作为表头               | 复选框   | 开启           | 仅导入时使用；作用于表格文件，导入的每一行会变成按列名取值的对象。                            |
| 起始数字                   | 数字     | `1`            | 数字序列来源的第一个值。                                                                      |
| 目标数字                   | 数字     | `10`           | 数字序列来源的最后一个值（含）；**起始数字**更大时倒序递减。                                  |
| 循环最大数据量（0 为不限） | 数字     | `0`            | 迭代上限；`0` 表示遍历全部数据。                                                              |
| 从索引开始                 | 数字     | `0`            | 先跳过这么多项。开启**恢复上一个工作流**时隐藏。                                              |
| 恢复上一个工作流           | 复选框   | 关闭           | 从上次记录的索引继续，未完成的那一项会重跑。                                                  |
| 倒序循环                   | 复选框   | 关闭           | 反向遍历数据源，且在起始索引与上限之前生效。                                                  |

### 输出

- `loopIndex` —— 在数据源中的绝对位置；跳过 3 项后的第一项是 `3`。
- `loopItem` —— 当前项：数据表行与 JSON 项是对象，数字区间是数字。页面元素来源把它设为 `null`。
- 只有一个输出端口：循环体。该循环没有 `end` 端口，循环结束后的走向见说明。

### Browser Copilot 说明

- **循环之后的路径**：由于只有一个输出，循环结束后运行从循环体内**循环断点**的出边继续。循环体里没有循环断点时，循环结束后运行无处可去。带上旧 `end` 端口导入的图仍可用那条边兜底。
- 数据来源：
  - **数据表**读取 `dataTable`；空表会记录一条提示并执行 0 轮。
  - **数字序列**生成闭区间，忽略起始索引、上限、倒序与恢复。
  - **变量**：数组按原样遍历；JSON 文本先解析；普通字符串按字符遍历；数字遍历 `1..N`。
  - **自定义数据**必须是 JSON 数组；为空或格式错误时运行失败并给出具体原因。
  - **页面元素**来源在循环开始时统计一次匹配数，并为每一项写入 `loopElementSelector`。
  - **Google 表格**在当前构建中被拒绝（需要 OAuth 凭据）；请把表格作为自定义数据导入。
- 准备顺序是：先倒序，再跳过**从索引开始**，最后应用**循环最大数据量**。数据源在循环开始时取快照，循环体追加的行不会被本轮遍历。
- **恢复上一个工作流**会在每一项的循环体执行前记录当前索引，因此中断的运行会重跑未完成的那一项；正常结束与**结束循环**都会清除该记录。
- 循环体内某一步失败会终止循环与运行，不经过循环之后的路径。
- 数字区间起止值无效、变量内容不可遍历或来源未知时，运行失败并指出是哪一处循环，见[错误、重试与可靠性](concepts.zh-CN.md#错误重试与可靠性)。

<!-- operator:loop-elements -->

## 循环元素

遍历定位器匹配到的每个元素，并把当前元素的选择器写入 `loopElementSelector`。[Automa 参考](https://www.goautoma.com/extension/docs/blocks/loop-elements.html)

### 设置

| 字段                                 | 类型     | 默认值        | 说明                                                             |
| ------------------------------------ | -------- | ------------- | ---------------------------------------------------------------- |
| 循环 ID                              | 文本     | 自动（6 位）  | 供**循环断点**定位本循环。                                       |
| 查找元素方式                         | 下拉选择 | `cssSelector` | `cssSelector`、`xpath` 或 `text`。                               |
| 选择器                               | 文本     | —             | 要遍历的集合的定位器，每个匹配项都会用到，支持 `{{variables}}`。 |
| 等待选择器                           | 复选框   | 关闭          | 由通用定位选项保存；匹配数在循环开始时统计一次，不会轮询。       |
| 选择器超时（毫秒）                   | 数字     | `5000`        | 仅在开启**等待选择器**时显示。                                   |
| 循环最大数据量（0 为不限）           | 数字     | `0`           | 迭代上限；`0` 表示遍历全部匹配项。                               |
| 倒序循环                             | 复选框   | 关闭          | 随算子保存；当前构建按文档顺序遍历。                             |
| 加载更多元素：操作                   | 下拉选择 | `none`        | `none`、点击元素、点击链接、向下滚动、向上滚动。只保存，见说明。 |
| 加载更多元素：元素选择器             | 文本     | —             | 两个点击操作会显示。                                             |
| 加载更多元素：等待更多元素的最长秒数 | 数字     | `5`           | 点击元素与两个滚动操作会显示。                                   |
| 加载更多元素：滚动到底部 / 顶部      | 复选框   | 开启          | 滚动操作会显示，标签随方向变化。                                 |
| 加载更多元素：等待页面加载的最长秒数 | 数字     | `10`          | 点击链接时显示。                                                 |

### 输出

- `loopIndex` —— 在匹配集合中从 0 开始的位置。
- `loopElementSelector` —— 指向当前元素的选择器，用于拼进循环体自己的定位器。
- 元素循环不写 `loopItem`。
- 只有一个输出端口：循环体。循环结束后的走向从循环体内的**循环断点**出边离开，与**循环数据**一致。

### Browser Copilot 说明

- 在循环体里这样使用：`{{loopElementSelector}} .price`，或作为点击 / 读取步骤的定位器。
- 匹配数在循环开始时统计一次；之后新增的元素不会被遍历。循环体执行期间才加载出来的内容需要另起一个循环。
- 某一轮无法生成唯一选择器时，循环会记录一条错误并把 `loopElementSelector` 留空；循环体会因未解析的标记失败，而不是悄悄重复第一个元素。
- **加载更多元素**区块与**倒序循环**会随工作流往返保存，但当前构建不执行。请在循环体末尾用**滚动元素**或点击步骤加载更多内容。
- 循环体内某一步失败会终止循环与运行，不经过循环之后的路径，见[错误、重试与可靠性](concepts.zh-CN.md#错误重试与可靠性)。

<!-- operator:loop-breakpoint -->

## 循环断点

在循环体内的任意位置结束当前这一轮，或结束整个循环。[Automa 参考](https://www.goautoma.com/extension/docs/blocks/loop-breakpoint.html)

### 设置

| 字段     | 类型   | 默认值 | 说明                                                                   |
| -------- | ------ | ------ | ---------------------------------------------------------------------- |
| 循环 ID  | 文本   | —      | 要结束的循环：填循环的**循环 ID**或其节点 id。留空则作用于最内层循环。 |
| 结束循环 | 复选框 | 关闭   | 关闭时跳过当前项剩余步骤，进入下一项；开启时直接离开整个循环。         |

### 输出

- 一个输出端口。对**循环数据**和**循环元素**来说，它就是循环之后的路径，因为这两种循环没有自己的 `end` 端口。
- 不写入变量。

### Browser Copilot 说明

- 在**循环数据**和**循环元素**中，循环结束后运行沿本节点的出边继续。只跳过当前项时，运行进入下一项，并把这条出边留到循环结束时使用；**结束循环**会立即跳到那条出边。
- 在 **While 循环**和**重复任务**中，离开循环走的是循环的 **end** 端口，而不是本节点的出边；跳过当前项仍会为 While 循环的上限计一轮。
- **循环 ID** 留空作用于最内层循环。填写外层循环的 ID 会一并解开内层循环，由外层循环接手处理。
- 不在任何循环内，或填写的 ID 匹配不到任何外层循环时，该算子会被忽略并记录一条提示，运行仍然成功。
- 该算子不会重试、不会失败、也不会走错误回退：它的哨兵异常绕过**出错时**，直接由循环捕获。见[错误、重试与可靠性](concepts.zh-CN.md#错误重试与可靠性)。
- 它不是调试断点。调试暂停来自块数据里的 `$breakpoint` 标记（在算子菜单里切换），会在测试运行到达该算子前暂停，与结束循环无关。检查点按每个已完成的步骤写入，因此恢复运行会从最后一个检查点之后的步骤继续。
