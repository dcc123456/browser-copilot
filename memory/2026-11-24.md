## 11:50 · fix(workflow): shed bulk payloads before a version snapshot is taken

- 变更：版本快照现在先跑与落盘同一套处理（`migrateWorkflow` + `shedBulkDataUrls`）**再算指纹、再计字节、再写键**——否则快照里带着内存中的原始 data URL（实测出现过 36MB 单图），用户看到的体积是假的，应用旧版还会把本该剥掉的数据装回画布；指纹基于"要落盘的形态"，同一个图不会算出两个哈希。256KB 单节点护栏保留，它管的是剥不掉的大字符串（shed 只认 `data:` URL，两者是不同阈值）。
- 模块：src/lib/workflow/workflow-versions.ts、src/lib/workflow/storage.ts、tests/workflow-versions.spec.ts
- 验证：新增 3 条单测（data URL 先剥再哈希、且与"已带占位符"的同一图指纹相同；300KB 非 data 字符串仍被 256KB 护栏拒；小 data URL 低于剥离阈值时原样保留）；typecheck / test（6188）/ build 绿。真机仍未跑。
- 遗留：`saveWorkflow` 本身不调用 `capPersistedStrings`，所以快照也**没有**加 8KB 字符串截断——刻意为之：加上会让快照内容与落盘内容不一致、应用旧版时截断真实代码；非 data 大字符串由 256KB 护栏兜底。
