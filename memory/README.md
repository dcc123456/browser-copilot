# 修改记忆目录 / Change memory

这里记录**最近改了什么、为什么改、验到哪一步**，让下一次修改（人或 AI）不用翻 `specs/` 和聊天记录
就能拿到上下文。**设计写进 `specs/`，这里只写发生过什么**——两者不要互相替代。

完整规则在 [`AGENTS.md` §9](../AGENTS.md#9-修改记忆目录--change-memory-memory)；本文件是同一份规则的精简版。

## 目录

```
memory/
  index.md          # 目录：一行一天；今天的行可改，历史行冻结
  2026-11-23.md     # 当天所有改动；一天只有一个文件，只追加
  README.md         # 本文件
```

## 每次代码提交要做什么

1. 在**当天文件**（`memory/YYYY-MM-DD.md`，本地时区）**追加**一条；
2. **更新 `index.md` 里今天那一行**（只改今天，历史行不动）。

### 条目格式（固定五项，多一项都不加）

```markdown
## 14:32 · feat(agent): require an explicit completion declaration

- 变更：用户可见的行为变化（不是文件清单）
- 模块：src/background/agent.ts、src/lib/task-progress.ts
- 验证：typecheck / test / build 绿；真机 <哪条判据>
- 遗留：<没做完的；没有就写"无">
```

- 标题里的时间用 **24 小时制 `HH:MM`**（本地时区），后面接 **commit subject 一字不差**。
- **不写 commit hash**：记忆是在同一次提交里写的，那一刻 hash 还不存在；事后用
  `git log --grep "<subject>"` 定位即可。
- 「变更」写**行为变化**：「现在点准星不会抢焦点」有意义；「改了 3 个文件」没有意义。
- 「验证」写**实际跑过的**命令与结论，以及真机判据（没跑就写"未验证"，不要写"应该可以"）。
- 「遗留」写清楚没做完的部分；没有就写「无」——不要省略这一项。

### index.md 的一行

```markdown
| 2026-11-23 | 显式完成声明 + 五条不变量 + tag 规则 | [详情](2026-11-23.md) |
```

## 四条硬规则

1. **标识用 commit subject，不写 hash**（理由见上）。
2. **只追加，不改历史**：昨天的文件、`index.md` 里昨天的行都冻结；只有今天那一行允许改。
3. **写行为变化，不写文件清单**。
4. **没有代码变化的纯文档提交不强制记**；但涉及**规则、发布口径、验收口径**的变更建议记一条，
   否则下一个人会以为它一直是这样。**同一天的 docs 提交可合并成一条**，标题写成
   `## 14:32 · docs: <概括>`（例如「设计/验收口径变更：五条不变量、P2 根因、tag 规则」），
   不要逐条列——这些提交的价值是"为什么"，逐条列会把重点埋掉。

## 回填历史（backfill）

从 `git log` 批量补历史时（`scripts/memory-backfill.mjs`）：

- 标题末尾加 **`（回填）`**；
- **`验证` 与 `遗留` 一律写「未记录」**——提交信息推不出当时跑没跑门禁，**不许写"绿/通过"**；
- `变更` 只写 subject 能确定的内容 + 涉及模块，不脑补动机；
- **已有条目一个字都不许动**，回填只新增。

回填的价值是**有索引**，不是有结论。编出来的「验证：绿」比没有记录更坏——后来的人会以为那件事验过。

## 常见问题

**同一天提交了多次怎么办？**
都追加到同一个当天文件，按时间从早到晚排列；`index.md` 里仍然只有今天一行，摘要随当天进展更新。

**跨天了但提交还没写完？**
以**该提交的提交时间**为准（本地时区）：`git log -1 --format=%ad --date=short`。
**不是写文件那一刻的墙钟日期**——今天补记昨天的提交，就写进昨天那个文件。
写错成墙钟日期会让整份日志歪一天，`git log --since/--until` 对不上任何一天，而且看起来完全正常。

**能不能事后补记昨天的？**
不能改昨天的文件（历史冻结）。如果是遗漏，写在今天的条目里并注明「补记 YYYY-MM-DD」。
