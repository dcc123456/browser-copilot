# v0.6.10 更新说明（自 v0.6.9 以来 / Changelog since v0.6.9）

> 本次提供**三种安装包**，按需下载：
>
> - `browser-copilot-0.6.10-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js），工作流 **OCR 识别**算子、离线验证码识别开箱即用。
> - `browser-copilot-0.6.10-no-ocr.zip` —— **Chrome 精简版**（约小 98%）：不含 OCR 引擎与语言模型，其余功能完全一致；OCR 算子置灰不可用，图片文字仍可通过视觉模型识别（设置 → 图片识别模型）。
> - `browser-copilot-0.6.10-firefox.xpi` —— **Firefox 版**（需 Firefox 128+）：由同一套源码构建，功能与精简版一致（Firefox 无 offscreen 文档，本地 OCR 不可用）；安装方法见下方「Firefox 安装」。
>
> Three packages ship this time: the usual two Chrome builds plus a Firefox
> 128+ build, built from the same sources and feature-identical to the lite
> Chrome build (local OCR is unavailable on Firefox).
>
> **Firefox 安装**：
>
> 1. **临时试用**（所有 Firefox 128+）：地址栏打开 `about:debugging#/runtime/this-firefox`，点「临时载入附加组件」，选择下载的 `.xpi`；重启浏览器后需重新载入。
> 2. **长期使用**（开发者版 / Nightly / ESR）：`about:config` 里把 `xpinstall.signatures.required` 设为 `false`，再到 `about:addons` → 右上角齿轮 → 「从文件安装附加组件」，选择该 `.xpi`。正式版 Firefox 只接受已签名扩展。
>
> **Installing on Firefox**: open `about:debugging#/runtime/this-firefox` and use
> "Load Temporary Add-on" with the `.xpi` (temporary, works on any Firefox
> 128+). For a permanent install, use Developer Edition / Nightly / ESR with
> `xpinstall.signatures.required` disabled in `about:config`, then
> `about:addons` → gear → "Install Add-on From File". Regular Firefox only
> installs signed add-ons.

## ✨ v0.6.10

这一版的主线是**工作流广场**：不新建任何服务器，用 GitHub 仓库当数据库，把工作流发布、浏览、应用、更新、讨论串起来。发布只需粘贴一次 classic PAT（`public_repo`），发布动作是开一个 PR，维护者手动合并后上架；已安装的用户会收到更新提示，并且更新是原地替换、保留本地身份。另有一组**存储可靠性修复**：切换存储文件夹会先迁移旧目录数据，扩展更新后目录权限降级会自动重连，编辑同一个工作流不再叠出两个互相覆盖的窗口。

### 🌐 工作流广场：零服务器的分享

- **发布**：工作流卡片的「发布」打开弹窗，填写分类、标签、封面、视频与附件后提交。扩展会自动 fork 仓库、建立提交分支、写入 `workflows/<slug>/` 下的 `meta.json` / `workflow.json` 并发起 PR；合并不在扩展里自动完成，由维护者审核后手动合并。
- **浏览**：侧边栏「更多 → 工作流广场」。支持搜索、按分类筛选与排序；卡片展示作者、类型、标签、点赞/评论数以及来源链接。目录读取每次只花 3 次 GitHub API 调用，工作流正文与图片走 raw 域名，不占额度。
- **应用**：首次应用必须确认「第三方工作流会在你的浏览器里执行页面操作」，并给出 GitHub 文件链接；写入本地后触发器一律默认关闭，永不自动运行。重复应用同一来源不会堆积副本。
- **更新**：发布者升版本号后，已安装的工作流在列表与卡片上显示「可更新」。如果工作流被下架后又以相同版本号重新发布（版本号是发布会复用的），也会通过内容 hash 识别出来；已发布版本低于本地记录时不会提示，避免缓存回退把用户降级。更新覆盖步骤、触发器与设置，保留本地 `id`、文件夹与创建时间，并写入一条 `marketplace-update` 修订记录。
- **重新编辑与取消发布**：作者本人可以在卡片上取消发布（发起删除文件的 PR）；重新编辑时标题、描述、分类、标签、视频、图片与附件会从已发布内容预填，改动后再发布会复用同一个 slug 并升版本号。
- **被调用的工作流**：如果工作流调用了其他工作流，发布会把被调用的工作流一并打包进同一个 PR，并在弹窗、卡片与确认文案里写明；应用时把这些调用重写到本机副本的确定性 id，重复更新替换同一份副本。缺少依赖会直接阻断发布。
- **附件**：发布时最多附带 3 个 ≤200 KB 的文件，随同一个 PR 提交；广场卡片把附件列成指向原始文件的链接，不写入本地库。
- **分类与点赞/评论**：内置分类更细，并支持发布者自定义分类；点赞与评论复用已合并 PR 的 reactions 与评论串，不需要额外服务。

### 🗂 存储可靠性

- **切换存储文件夹不再丢数据**：换目录前先读取旧目录并迁移到新目录（集合按记录合并、对话与检查点整体迁移、技能/智能体按文件落地、配置不动）；旧目录权限待确认时在同一次点击里重新授权，无法授权则拒绝切换并提示重连，而不是静默丢掉唯一副本。
- **切换后写回旧目录的问题修复**：目录变更/移除会广播到所有上下文并丢弃后台缓存的目录句柄。
- **扩展更新后的自动重连**：更新会把文件夹权限降级为 `prompt`；面板重新可见、窗口重新获得焦点时都会重试连接，不再需要手动点一下面板。
- **不再叠出两个编辑器窗口**：编辑已打开的工作流会聚焦已有窗口，避免两份副本互相覆盖；新建工作流后立即记录编辑器 URL 的 id，点击「编辑」聚焦同一个窗口。

### 🐞 其他修复

- 广场目录读取：修掉「PR 刚合并却要等 5 分钟才出现」的问题（raw 域名的 404 也会被缓存 5 分钟）；树里有工作流却解析不出任何卡片时按读取失败处理，绝不把空目录写进 30 分钟缓存。
- 空仓库被当作空目录而不是加载失败；GitHub 连接失败会给出具体原因。
- README 补充安装与演示说明。

## English summary

**v0.6.10** adds the workflow marketplace — sharing without a new server. The
public GitHub repository is the database: publishing opens a pull request, the
maintainer merges it by hand, and everyone else browses 工作流广场, applies a
copy locally (trust prompt first, triggers disabled, never auto-run) and
receives update reminders. Updates compare the published version, plus the
content hash at the same version so a listing that was removed and re-added
under an old number still reaches installed users. This release also fixes
folder-switch data loss, post-update folder reconnects and duplicate editor
windows.

- **Marketplace**: publish a workflow (category, tags, cover, video, up to three
  attachments of 200 KB) from the workflow card; the extension forks the repo,
  writes `workflows/<slug>/` and opens a PR. The marketplace lists cards with
  author, category, tags and engagement, search/filter/sort, likes and comments
  through the merged PR, and an unpublish/re-edit flow for the author. A
  published workflow that calls other workflows bundles them into the same PR,
  and applying it rewrites those calls to deterministic local copies. Catalog
  reads cost three API calls, cache for 30 minutes and fall back to the last
  snapshot offline.
- **Storage reliability**: switching the storage folder now carries the
  departing folder's records first, re-grants a pending permission in the same
  click and refuses the switch rather than dropping the only copy; directory
  changes are announced to every context so background writes stop landing in
  the old folder; a permission downgraded by an extension update is retried when
  the panel becomes visible or the window regains focus; editing an open
  workflow focuses the existing editor window instead of opening a second copy.
- **Fixes**: raw-host caching no longer hides a just-merged workflow for five
  minutes; an all-missing metadata read is treated as a failure instead of
  caching an empty catalog; an empty repository is an empty catalog; GitHub
  connection failures report the real cause; README installation and demo notes.
