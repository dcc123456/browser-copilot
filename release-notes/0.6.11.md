# v0.6.11 更新说明（自 v0.6.10 以来 / Changelog since v0.6.10）

> 本次提供**三种安装包**，按需下载：
>
> - `browser-copilot-0.6.11-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js），工作流 **OCR 识别**算子、离线验证码识别开箱即用。
> - `browser-copilot-0.6.11-no-ocr.zip` —— **Chrome 精简版**（约小 98%）：不含 OCR 引擎与语言模型，其余功能完全一致；OCR 算子置灰不可用，图片文字仍可通过视觉模型识别（设置 → 图片识别模型）。
> - `browser-copilot-0.6.11-firefox.xpi` —— **Firefox 版**（需 Firefox 128+）：由同一套源码构建，功能与精简版一致（Firefox 无 offscreen 文档，本地 OCR 不可用）；安装方法见下方「Firefox 安装」。
>
> Three packages ship this time: the usual two Chrome builds plus a Firefox
> 128+ build, built from the same sources and feature-identical to the lite
> Chrome build (local OCR is unavailable on Firefox).
>
> **Firefox 安装**：
>
> 1. **临时试用**（所有 Firefox 128+）：地址栏打开 `about:debugging#/runtime/this-firefox`，点「临时载入附加组件」，选择下载的 `.xpi`；重启浏览器后需重新载入。
> 2. **长期使用**（开发者版 / Nightly / ESR）：`about:config` 里把 `xpinstall.signatures.required` 设为 `false`，再到 `about:addons` → 右上角齿轮 → 「从文件安装附加组件」，选择该 `.xpi`。正式版 Firefox 只接受已签名扩展。
>
> **Installing on Firefox**: open `about:debugging#/runtime/this-firefox` and use
> "Load Temporary Add-on" with the `.xpi` (temporary, works on any Firefox
> 128+). For a permanent install, use Developer Edition / Nightly / ESR with
> `xpinstall.signatures.required` disabled in `about:config`, then
> `about:addons` → gear → "Install Add-on From File". Regular Firefox only
> installs signed add-ons.

## 🔄 v0.6.11

这一版处理的是**同一出口 IP 上的 GitHub 匿名额度**：未登录的 API 只有 60 次/小时，更新检查与工作流广场共用这一份，两边一起用就会互相饿死。旧版一旦被限流，只会记录一次失败然后等 12 小时，所以面板会长期停在「上次检查：3 天前」。本版把日常检查改成不花额度、失败后自动重试，并让广场在回退缓存时说出真实原因。

### 🔄 更新检查

- **日常检查不再消耗 API 额度**：跟随公开的 `github.com/.../releases/latest` 跳转拿到最新 tag，没有新版本就直接结束；只有确实存在新版本时，才调用一次 API 取附件摘要与更新说明。探针不可用时仍回退到原来的 API 路径。
- **失败自动重试**：限流时按 GitHub 给出的 `x-ratelimit-reset` 安排重试，网络或其他失败按 15 分钟 → 6 小时的指数退避；成功一次即清零。
- **面板自愈**：打开侧边栏或设置页时，如果状态已超过 12 小时、或重试时间已到，会自动重新检查，不再需要等下一个闹钟。
- **仍停在 0.6.8 的旧安装**：旧版无法自己恢复时，直接下载上面的 0.6.11 安装包覆盖安装即可（安装目录不变，本地工作流与设置保留）。

### 🌐 工作流广场

- **目录新鲜窗口放宽到 2 小时**（原 30 分钟）：一次刷新花 3 次 API 调用，与更新检查共用额度，因此不再频繁自动重拉；右上角刷新按钮始终立即生效。
- **回退缓存时说明真实原因**：限流会显示「GitHub 限流，预计 HH:MM 恢复」，网络故障会显示具体原因，而不是一律说「无法连接 GitHub」。缓存卡片继续保持可浏览、可应用。

## English summary

**v0.6.11** fixes the shared GitHub anonymous quota. Unauthenticated API
requests are capped at 60/hour per egress IP, and update checks spent that
budget alongside the workflow marketplace, so a rate-limited check could leave
the panel showing a check from days ago with no retry. A routine update check
now follows the public `/releases/latest` redirect and costs no API quota,
asking the API only when a newer tag exists; failures retry at GitHub's reset
time or with 15-minute-to-6-hour backoff, and opening the panel re-checks a
state older than 12 hours on its own. The marketplace keeps its catalog for 2
hours instead of 30 minutes and, when it falls back to cached cards, names the
real failure — including the rate-limit reset time — instead of a generic
"could not reach GitHub".

- **Update checks**: quota-free latest-tag probe via the releases redirect;
  API only for the asset digest and notes when a newer tag exists; retries at
  the server's reset time or with exponential backoff up to 6 hours; the panel
  and settings card heal a stale state automatically.
- **Marketplace**: 2-hour catalog freshness window (manual refresh bypasses
  it) and a truthful stale banner with the rate-limit reset time.
