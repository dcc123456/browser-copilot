# v0.6.12 更新说明（自 v0.6.11 以来 / Changelog since v0.6.11）

> 本次提供**三种安装包**，按需下载：
>
> - `browser-copilot-0.6.12-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js），工作流 **OCR 识别**算子、离线验证码识别开箱即用。
> - `browser-copilot-0.6.12-no-ocr.zip` —— **Chrome 精简版**（约小 98%）：不含 OCR 引擎与语言模型，其余功能完全一致；OCR 算子置灰不可用，图片文字仍可通过视觉模型识别（模型设置 → 图片识别模型）。
> - `browser-copilot-0.6.12-firefox.xpi` —— **Firefox 版**（需 Firefox 128+）：由同一套源码构建，功能与精简版一致（Firefox 无 offscreen 文档，本地 OCR 不可用）；安装方法见下方「Firefox 安装」。
>
> Three packages ship this time: the usual two Chrome builds plus a Firefox
> 128+ build, built from the same sources and feature-identical to the lite
> Chrome build (local OCR is unavailable on Firefox).
>
> **Firefox 安装**：
>
> 1. **临时试用**（所有 Firefox 128+）：地址栏打开 `about:debugging#/runtime/this-firefox`，点「临时载入附加组件」，选择下载的 `.xpi`；重启浏览器后需重新载入。
> 2. **长期使用**（开发者版 / Nightly / ESR）：`about:config` 里把 `xpinstall.signatures.required` 设为 `false`，再到 `about:addons` → 右上角齿轮 → 「从文件安装附加组件」，选择该 `.xpi`。正式版 Firefox 只接受已签名扩展。
>
> **Installing on Firefox**: open `about:debugging#/runtime/this-firefox` and use
> "Load Temporary Add-on" with the `.xpi` (temporary, works on any Firefox
> 128+). For a permanent install, use Developer Edition / Nightly / ESR with
> `xpinstall.signatures.required` disabled in `about:config`, then
> `about:addons` → gear → "Install Add-on From File". Regular Firefox only
> installs signed add-ons.

## 🛒 v0.6.12

这一版把**分享**和**定时**两件事补齐了：工作流广场终于可以带着凭据发布、发布草稿不会丢；定时任务一条记录能挂多个触发方式，并支持 cron 表达式。同时编辑器补上了「有没有保存」「录制结果去哪了」这两个长期困惑，聊天里每一轮回复都能复制导出了。

### 🛒 工作流广场：凭据随包发布，草稿不再丢

- **凭据跟着工作流走**：发布用到存储凭据的工作流时，发布框会列出被引用的凭据与字段名，随清单一并提交；密码类字段默认留空，其余字段默认取本地值，都可以改，填了密码会照旧弹出「仍然发布」警告。应用这类清单时会先把凭据导入本地保险库，再把父工作流及其打包子工作流里的 `get-secret` 步骤改写到导入后的 id，跑起来不用再挑一次凭据。重复应用只补缺失字段，已填的值不动。
- **导入后立刻可见**：后台写入的凭据以前要刷新面板才出现；数据页与已打开的 `get-secret` 表单现在会监听保险库变化并就地刷新。
- **打包工作流自成一组**：应用一个会调用其他工作流的清单时，会以父工作流名字新建分组，把父与所有打包进来的子工作流放进去；同名分组会复用，更新应用不会改变你手动放好的位置。
- **发布草稿**：中途关掉发布框会保存标题、描述、分类、标签、视频链接、截图与附件作为该工作流的草稿，再次打开发布框自动恢复（草稿优先于上次发布的文案）；发布成功、手动「丢弃草稿」或 30 天不动会清除，最多保留 8 份。
- **维护者发布即上线**：GitHub 令牌可写广场仓库时（目前就是维护者本人），发布流程会在开 PR 后直接合并，工作流立即生效并清掉缓存；第三方投稿仍然保持 PR 待审。把 `MARKETPLACE_AUTO_MERGE_PULLS` 设为 `false` 可让所有人回到审核流。
- **卡片操作图标化**：GitHub 链接变成工作流名旁的图标，点赞与评论是带计数的图标按钮并排放在操作行；点赞控件从讨论面板移出（那里只剩评论），所有者操作改名为「下架」。

### ⏰ 定时任务：一条任务多个触发方式 + cron

- **多触发方式**：任务编辑里可以添加多条触发方式，每条独立触发一次运行（就是「每加一个触发方式＝多一次定时运行」），列表按方式各显示一个标签。顶层 `schedule` 仍是第一条的镜像，所以旧记录无需迁移、老读取方照常工作；每条一个闹钟，统一清扫重挂，删掉或用尽的条目不会留下过期闹钟。
- **cron 表达式**：支持五段式 cron（本地时区），「每月 1 号」「每两小时」这类预设表达不了的节奏不用再拼伪周计划；复用 Runner 已在用的 `croner`，不引入第二套引擎。写错的表达式会保留在编辑框里提示你，但不会被挂载、也会阻止保存；永远不可能命中的日期（2 月 31 日）不挂载并给出说明。Agent 工具 `create_scheduled_task` 同步支持 `kind: "cron"`，并会拒绝畸形表达式而不是存下来。
- 每条触发方式卡片的移除按钮改为垃圾桶图标（带双语无障碍名称与提示）。

### 🧩 模型设置独立成页

供应商、图片识别模型与 AI 接管模型从「设置」搬进「更多」菜单里的**模型设置**，两页共用同一份配置存储。新增供应商菜单把自定义端点排到最后，拉取到的模型变成复选框列表，可以一次勾选多个添加。

### ✏️ 工作流编辑器：看得出没保存，录制并进画布

- **保存按钮带脏标记**：画布与磁盘内容不一致时按钮会提示；判据是内容指纹，React Flow 的测量渲染不会把刚打开的工作流误标成未保存。
- **录制结果直接进当前画布**：录制到的步骤会接在唯一的终止节点之后追加到打开的画布，不再另存一份工作流。
- **底部居中工具条**：撤销 / 重做 / 自动布局集中一处；自动布局会避开左侧组件面板、只适配剩下的画布区域，缩放控件移到小地图左侧。
- **数据表标签**：解释运行级变量的作用域，并列出每个变量的写入方、读取方与写入列，可一键跳到对应节点。侧边栏头部显示可复制的工作流 id。
- **触发器只编辑一个**：触发器块去掉了旁边的「工作流触发器」列表弹窗，任何修改都只写一份启动配置（这才是调度器真正能挂载的形态）；导入的多触发图保留主配置并说明情况。
- **Webhook 面板重做**：对齐 Automa 的 HTTP 请求块——分段式标签条、七列网格的请求头行（图标删除 + 整宽新增按钮）、内嵌 body 预览并可弹窗编辑 body；切到 GET/HEAD 会退回请求头标签，不再留下悬空的空面板。

### 💬 聊天：每一轮都能复制导出

复制与下载从气泡内部移到**该轮回复的下方**，默认隐藏、鼠标悬停或键盘聚焦时淡入——和你的消息一样，每一轮都有自己的操作行；下载菜单改为向上弹出。以前只有最新一条回复能导出，现在任意一轮都可以。

### 🐛 修复

- **推理 token 一直是 0**：OpenAI 与 DeepSeek 把推理计费在补全里、通过 `completion_tokens_details.reasoning_tokens` 上报，而用量解析只读提示词侧字段，所以聊天底部的推理量永远显示 0；现在优先读补全侧，旧字段保留为其他网关的回退。
- **新建分组与批量移动图标混淆**：两者都和「新建工作流」用同一个加号；现在新建分组是「文件夹＋加号」，批量移动是「文件夹＋箭头」。

### 📖 文档

两个 README 补充「如何升级安装且不掉数据」：0.6.8 起的原地更新器，以及更老安装需要的一次性手动换目录；并说明为什么原地替换能保留扩展 id（连同其存储数据），而从别的目录加载新 zip 或移动当前目录都不行。

## English summary

**v0.6.12** completes sharing and scheduling. The workflow marketplace can now
publish a workflow **together with the credentials it uses**, keeps a **draft**
when you close the publish dialog, files a bundled workflow into **its own
group**, and merges the maintainer's own pull request so a publish goes live
immediately. A scheduled task can carry **several trigger methods**, each firing
its own run, and five-field **cron** expressions join the presets. Model
settings moved into their own tab, the workflow editor finally shows whether the
graph is unsaved and appends recorded steps to the open canvas, and every chat
round gets its own copy/download row again.

- **Marketplace**: credentials travel with the listing and are imported (and
  rewired) on apply; vault edits refresh open forms without a reload; bundles
  land in a group named after the parent; publish drafts survive a closed
  dialog; the maintainer's publish auto-merges; card actions became icons.
- **Scheduling**: one task → many trigger methods (one alarm each, `schedule`
  stays the first entry's mirror), local-time five-field cron via the Runner's
  existing `croner`, invalid text blocks saving instead of arming, and
  `create_scheduled_task` learned `kind: "cron"`.
- **Editor**: dirty-state Save marker, record appends to the open graph,
  undo / redo / auto-layout bar, a Data table tab of variable writers and
  readers, copyable workflow id, single-trigger editing, and an Automa-style
  webhook header/body panel.
- **Chat**: copy and download moved below each round, hover-revealed, so any
  earlier reply is exportable; the download picker opens upward.
- **Fixed**: reasoning tokens always showed zero (they are reported under
  `completion_tokens_details`), and "new group" vs "batch move" icons now
  differ.
- **Docs**: both READMEs explain how to upgrade an install without losing data.
