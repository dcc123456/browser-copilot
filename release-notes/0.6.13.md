# v0.6.13 更新说明（自 v0.6.12 以来 / Changelog since v0.6.12）

> 本次提供**三种安装包**，按需下载：
>
> - `browser-copilot-0.6.13-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js），工作流 **OCR 识别**算子、离线验证码识别开箱即用。
> - `browser-copilot-0.6.13-no-ocr.zip` —— **Chrome 精简版**（约小 98%）：不含 OCR 引擎与语言模型，其余功能完全一致；OCR 算子置灰不可用，图片文字仍可通过视觉模型识别（模型设置 → 图片识别模型）。
> - `browser-copilot-0.6.13-firefox.xpi` —— **Firefox 版**（需 Firefox 128+）：由同一套源码构建，功能与精简版一致（Firefox 无 offscreen 文档，本地 OCR 不可用）；安装方法见下方「Firefox 安装」。
>
> Three packages ship this time: the usual two Chrome builds plus a Firefox
> 128+ build, built from the same sources and feature-identical to the lite
> Chrome build (local OCR is unavailable on Firefox).
>
> **Firefox 安装**：
>
> 1. **临时试用**（所有 Firefox 128+）：地址栏打开 `about:debugging#/runtime/this-firefox`，点「临时载入附加组件」，选择下载的 `.xpi`；重启浏览器后需重新载入。
> 2. **长期使用**（开发者版 / Nightly / ESR）：`about:config` 里把 `xpinstall.signatures.required` 设为 `false`，再到 `about:addons` → 右上角齿轮 → 「从文件安装附加组件」，选择该 `.xpi`。正式版 Firefox 只接受已签名扩展。
>
> **Installing on Firefox**: open `about:debugging#/runtime/this-firefox` and use
> "Load Temporary Add-on" with the `.xpi` (temporary, works on any Firefox
> 128+). For a permanent install, use Developer Edition / Nightly / ESR with
> `xpinstall.signatures.required` disabled in `about:config`, then
> `about:addons` → gear → "Install Add-on From File". Regular Firefox only
> installs signed add-ons.

## ⌨️ v0.6.13

这一版的主线是**聊天输入框**：它从「打字的盒子」变成了命令入口——敲 `/` 调出命令与技能，选一个技能就变成输入框里的一枚 tag 并只作用于这一条消息；`/compact` 把上下文压缩搬进了这条命令，工具条上的旧按钮随之消失；`@` 直接唤起附件选择。同一行里的模式、模型、新建、发送在任何面板宽度下都保持一行。此外还有团队私有仓库共享工作流、分组删除的连带清理，以及三处会悄悄咬人的修复。

### 💬 输入框：`/` 命令、技能 tag、`@` 附件、模型选择器

- **一个 `/` 菜单装下命令与技能**：输入 `/` 弹出同一个选择器，既有你保存的技能，也有内置的 `/compact`（会话里还没内容可压时不出现）。上下键移动、回车选中；选中行是浅色底的圆角块加左侧强调色条，命令名用强调色，深浅两套主题都清楚可读。
- **技能是一次性的**：选中 `/trans` 后，草稿里的 `/tr` 被吃掉，技能以 `/trans` tag 的形式钉在输入框的**第一行**——输入框仍是满宽，只有首行从 tag 后面开始，长草稿会让输入框自己长高而不是滚到 tag 底下。这条消息带着技能发出，转写里那一轮保留 `/trans` tag，下一条消息不再带着它。chat 模式下钉住的技能说明现在真的会进模型的 system prompt，而不是被短身份句挤掉。
- **`@` 唤起附件**：在词首敲 `@` 直接打开文件选择器，`@` 本身不会进入正文；回形针按钮删除，placeholder 同时说明 `/` 与 `@` 两个手势。
- **模型选择器**：输入框右侧列出「模型设置」里所有供应商的全部模型，按供应商分组；选中即切换当前模型，下一条回复就用它生成。保存失败会把选择回滚并提示，不会让输入框显示一个实际没用上的模型。
- **始终一行**：模式选择、模型选择、新建对话、发送在面板拖到最窄（约 320px）时仍排在一行——空间不足时先省略模型名，模式名尽量保留，发送与文字按钮的标签保持完整。
- **一个焦点框**：聚焦输入框时只有字段容器那一圈蓝色焦点框，不再在框内多出一圈灰框；新会话用加号图标，发送是图标按钮。

### 🗜️ 上下文压缩：按模型真实窗口触发，也能手动压

- **按真实窗口自动压**：以前的触发线是「假设 256K 窗口的 80%」，跟你实际配置的模型毫无关系——32K、128K 的模型永远够不到它，对话一直涨到供应商直接报错为止。现在会话会记住供应商在拒收时自己声明的上限，从下一轮起按该窗口的 **90%** 压缩，赶在再次失败之前。
- **`/compact` 手动压**：敲 `/compact` 跑的就是自动触发那套压缩——较早轮次的回复与工具结果折成一段摘要，你打的字原样保留——长对话可以在窗口填满前先瘦身。toast 会报告替换了多少条，没东西可压或还有回复在跑时会说明；正在流式输出的回复不会被改写。

### ✍️ 回复被截断时不再静默

两种「说到一半就没了」的情况。常见的一种是供应商自己的输出上限：流是正常结束的，客户端于是把半截回答当成了完整回答。现在聊天会从它写到的最后一个字符开始请求续写——每条回复最多三次，不占用重连预算——并在状态行说明；如果仍被上限截住，面板会明说回复可能不完整，而不是假装它已经结束。另一种是代理不关连接直接掉线：请求会永远挂着。聊天请求现在连续 120 秒没有任何数据就中断重连，与助手原本的静默窗口一致——只要还在持续输出，跑多久都不会被切断。

### 👥 工作流广场：团队私有仓库

广场多了一个来源：一个**私有 GitHub 仓库**，协作者就是团队。在「设置 → 团队共享」里填入带 `repo` scope 的 classic token 即可连接；读取走带鉴权的 contents API，因此只有 GitHub 允许进入该仓库的人能看到清单，广场标签页在公共广场与团队来源之间切换。应用团队工作流时，其捆绑的子工作流与凭据会照常导入；发布到团队会直接对该仓库开 PR，token 有推送权限时自动合并，只读成员则留给维护者审核。发布草稿按目标分别保存，给一个仓库填过的凭据值不会出现在另一个仓库的发布框里。

### 🗂 删除分组连带其工作流

删除工作流分组以前只是把组删掉，组里的工作流会重新出现在未分组列表里。现在删除分组会一并删掉其中的工作流，确认框里写明分组名与随之删除的工作流数量，动手之前就能看清连锁范围。

### 🔄 原地更新的备份会自己清理

原地更新会把被替换的文件备份在安装目录里。现在这份备份在写入时就登记，新版本下**第一次打开面板**即证明重载成功，备份随之删除；旧版本仍在运行、或目录权限还没授予时备份会保留，回滚副本不会在安全之前被过早清掉。

### 🐛 修复

- **MiniMax 国际站端点**：预设提供的是 `api.minimax.io`，而供应商识别只认识 `.minimaxi.com`、`.minimax.cn`、`.minimax.chat`，于是该端点被当成未知供应商：思考档位全都列出来，并且「关闭」会发成通用的 `reasoning_effort: "none"`，MiniMax 在 M3.1 上对此直接回 400。现在该域名已纳入映射，并用基于真实 API 回包的测试钉住。

## English summary

**v0.6.13** turns the chat composer into a command surface. Typing `/` opens one
picker for saved skills and the built-in `/compact`; picking a skill turns it
into a tag pinned to the input's first line and applies it to that one message
only — the field keeps its full width, grows with the draft, and the transcript
keeps the `/trans` tag on the turn. `@` opens the file picker (the character
never enters the draft), a model picker sits next to send, and the action row
stays on a single line even at the panel's narrowest. Alongside it: team
workflows from a private repository, group deletion that takes its workflows
with it, compaction driven by the model's real window (plus an on-demand
`/compact`), replies that continue instead of ending half-way, and a MiniMax
international-endpoint fix.

- **Composer**: one `/` menu for commands and skills; one-shot skill tags on the
  first line; `@` for attachments; grouped model picker that applies
  immediately and rolls back on failure; mode, model, new chat and send kept on
  one row at minimum width; a single focus frame; plus icon for a new chat.
- **Compaction**: automatic trigger now follows the window the provider itself
  states (90%), and `/compact` runs the same pass on demand.
- **Replies**: a capped reply is continued from its last character (up to three
  times) and reported as possibly incomplete if still cut; a silent connection
  reconnects after 120 seconds.
- **Marketplace**: a private team repository as a second source — authenticated
  reads, apply with bundles and credentials, publish as a PR (auto-merged when
  the token can push), drafts kept per target.
- **Changed**: deleting a group removes its workflows, with a confirmation that
  counts them; update backups delete themselves once the new build has proven it
  opens.
- **Fixed**: `api.minimax.io` is recognised as MiniMax, so thinking levels and
  the "off" body no longer trigger a 400 on M3.1.
