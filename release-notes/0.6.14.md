# v0.6.14 更新说明（自 v0.6.13 以来 / Changelog since v0.6.13）

> 本次提供**三种安装包**，按需下载：
>
> - `browser-copilot-0.6.14-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js），工作流 **OCR 识别**算子、离线验证码识别开箱即用。
> - `browser-copilot-0.6.14-no-ocr.zip` —— **Chrome 精简版**（约小 98%）：不含 OCR 引擎与语言模型，其余功能完全一致；OCR 算子置灰不可用，图片文字仍可通过视觉模型识别（模型设置 → 图片识别模型）。
> - `browser-copilot-0.6.14-firefox.xpi` —— **Firefox 版**（需 Firefox 128+）：由同一套源码构建，功能与精简版一致（Firefox 无 offscreen 文档，本地 OCR 不可用）；安装方法见下方「Firefox 安装」。
>
> Three packages ship this time: the usual two Chrome builds plus a Firefox
> 128+ build, built from the same sources and feature-identical to the lite
> Chrome build (local OCR is unavailable on Firefox).
>
> **Firefox 安装**：
>
> 1. **临时试用**（所有 Firefox 128+）：地址栏打开 `about:debugging#/runtime/this-firefox`，点「临时载入附加组件」，选择下载的 `.xpi`；重启浏览器后需重新载入。
> 2. **长期使用**（开发者版 / Nightly / ESR）：`about:config` 里把 `xpinstall.signatures.required` 设为 `false`，再到 `about:addons` → 右上角齿轮 → 「从文件安装附加组件」，选择该 `.xpi`。正式版 Firefox 只接受已签名扩展。
>
> **Installing on Firefox**: open `about:debugging#/runtime/this-firefox` and use
> "Load Temporary Add-on" with the `.xpi` (temporary, works on any Firefox
> 128+). For a permanent install, use Developer Edition / Nightly / ESR with
> `xpinstall.signatures.required` disabled in `about:config`, then
> `about:addons` → gear → "Install Add-on From File". Regular Firefox only
> installs signed add-ons.

## 🎯 v0.6.14

这一版把**页面元素**变成了可以直接喂给 agent 的材料：设置里打开后，任何网页右下角都会出现一个准星按钮，点它选中元素，就能把 CSS 选择器、可见文本或整段 HTML 复制到剪贴板，粘进聊天即可。顺带把三个需要填路径或凭据的设置卡片提到最前，并修掉了两个会让人摸不着头脑的问题。

### 🎯 页面元素选择：选中即复制，三种格式

- **设置里一键开启**：「设置 → 页面元素选择」打开后，网页右下角出现准星按钮；关掉即从所有标签页移除，无需刷新。
- **点一下开始选，确认后进剪贴板**：悬停高亮当前元素，点击锁定（再次点击可换），按回车或点卡片上的复制按钮提交；Esc 或 × 随时取消。锁定后卡片会显示该元素的选择器与本次复制的字符数。
- **复制格式可选**：开关下方的「确认后复制」三选一——**仅 CSS 选择器**（能唯一定位该元素的选择器）、**仅文本**（元素范围内的可见文字）、**HTML（标签 + 文本，含全部子元素）**。默认是 HTML，也就是「把这个元素下的内容整段拿走」的用法；切换后立即对已打开的页面生效。
- **大元素不静默**：复制内容超过 10 万字符时卡片会醒目提示可能偏大，但依然执行复制，不会悄悄换成截断或失败。
- **和插件按钮叠成一列**：准星与最小化后的插件圆形按钮默认都停在浏览器右下角，准星在上。拖动插件按钮时准星会跟着一起走、保持 8px 间距；只有把按钮拖到贴住顶边、上方放不下时，准星才临时翻到下方。

### ⚙️ 设置顺序：先填路径与凭据

「下载目录」「本地 Agent 接入」「团队共享」三张卡片提到设置最前。这三项决定了文件落在哪、agent 能不能连、团队仓库能不能读到，属于「不配就不完整」的项，现在排在语言、主题、行为开关之前。

### 🐛 修复

- **最小化后只剩准星、插件圆形按钮消失**：在扩展重载前就打开的标签页里，开启元素选择只会补注入准星脚本；此后最小化广播 `floating.show` 时，准星脚本的监听让后台误以为「悬浮按钮已送达」，于是跳过补注入。现在两个内容脚本都会对自己的控制消息回执，后台按「有没有目标脚本的回执」决定是否补注入，两个方向都不会再漏。
- **一分钟内重复发布更新会撞分支**：同为 `submit/<slug>-YYYYMMDDHHmm` 的分支名会让第二次发布收到 409/422，并显示笼统的「存在冲突」。分支名现在精确到秒；冲突提示也会说明处理办法（等一分钟，或先合并/关闭该工作流已打开的 PR）。

## English summary

**v0.6.14** turns any page element into material for the agent. Switch on the
page-element picker in Settings and a crosshair button appears in the
bottom-right corner of every page; hovering highlights, clicking locks, and the
confirm action copies the payload to the clipboard for pasting into chat. The
payload is configurable right under the toggle — the CSS selector only, the
visible text only, or the element's HTML including tags, text and descendants
(the default) — and the locked card shows the selector and payload size, with a
warning above 100,000 characters. The crosshair and the minimized plugin's
restore button now form one bottom-right stack that moves together when the
plugin button is dragged, flipping below only at the top edge. Download folder,
local agent access and team sharing moved to the top of Settings.

- **Element picker**: toggle in Settings; crosshair on every page in the
  bottom-right corner; hover to highlight, click to lock, Enter or the confirm
  button to copy; Esc or × to cancel. Copy as a unique CSS selector, the
  visible text, or the subtree HTML (default), switchable at any time and
  applied to already-open pages.
- **One stack**: the crosshair sits above the plugin restore button, follows it
  while it is dragged, and only flips below when the button touches the top
  edge. Dragged positions are still restored per window.
- **Settings order**: download folder, local agent access and team sharing are
  the first cards.
- **Fixed**: a minimized panel could lose its restore button when only the
  picker launcher had been reinjected into a tab — both content scripts now
  return a receipt and the worker reinjects the script that is actually
  missing. Publishing the same workflow update twice within a minute no longer
  collides on a reused branch (stamps now include seconds), and the conflict
  message spells out the recovery steps.
