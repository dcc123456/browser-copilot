# v0.6.16 更新说明（自 v0.6.15 以来 / Changelog since v0.6.15）

> 本次提供**三种安装包**，按需下载：
>
> - `browser-copilot-0.6.16-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js），工作流 **OCR 识别**算子、离线验证码识别开箱即用。
> - `browser-copilot-0.6.16-no-ocr.zip` —— **Chrome 精简版**（约小 98%）：不含 OCR 引擎与语言模型，其余功能完全一致；OCR 算子置灰不可用，图片文字仍可通过视觉模型识别（模型设置 → 图片识别模型）。
> - `browser-copilot-0.6.16-firefox.xpi` —— **Firefox 版**（需 Firefox 128+）：由同一套源码构建，功能与精简版一致（Firefox 无 offscreen 文档，本地 OCR 不可用）；安装方法见下方「Firefox 安装」。
>
> Three packages ship this time: the usual two Chrome builds plus a Firefox
> 128+ build, built from the same sources and feature-identical to the lite
> Chrome build (local OCR is unavailable on Firefox).
>
> **Firefox 安装**：
>
> 1. **临时试用**（所有 Firefox 128+）：地址栏打开 `about:debugging#/runtime/this-firefox`，点「临时载入附加组件」，选择下载的 `.xpi`；重启浏览器后需重新载入。
> 2. **长期使用**（开发者版 / Nightly / ESR）：`about:config` 里把 `xpinstall.signatures.required` 设为 `false`，再到 `about:addons` → 右上角齿轮 → 「从文件安装附加组件」，选择该 `.xpi`。正式版 Firefox 只接受已签名扩展。
>
> **Installing on Firefox**: open `about:debugging#/runtime/this-firefox` and use
> "Load Temporary Add-on" with the `.xpi` (temporary, works on any Firefox
> 128+). For a permanent install, use Developer Edition / Nightly / ESR with
> `xpinstall.signatures.required` disabled in `about:config`, then
> `about:addons` → gear → "Install Add-on From File". Regular Firefox only
> installs signed add-ons.

## 🎯 v0.6.16

这一版围绕**少花 token、少打扰你**：半自动不再逐个动作问，只对付款、密码、删除、发送这类有风险的动作确认；只读模式干脆不把任何写操作工具发给模型；专项页面工具改为按组按需加载，首轮提示词明显变小。另外补上了从卡片直接终止运行、设置里的目录快捷入口和安装信息，以及工作流广场的多团队支持。

### 🛡 半自动：只问有风险的动作

- **读页面、滚动不再确认**：读取页面、页面快照、截图/识图、滚动、等待、导航、标签页管理、保存文件，以及有明确按钮名的普通点击/填写——都直接执行，不再弹确认卡。
- **只有这些会先问**：付款/提交订单、填写密码或验证码（包括填入已保存凭据）、删除/重置/注销、发送/发布、执行页面脚本、创建技能或定时任务。
- **认不出的元素按风险处理**：既没有可识别名称、也不是密码框的元素动作会先确认，而不是猜；纯 CSS 选择器的目标即使认不出名称，只要命中付款/删除/发送类关键字也照样确认。
- **一整步到位**：`run_plan` 只要其中有一步有风险，就为整张计划弹一次确认；按 Enter 视为「提交」，方向键等不受影响。
- **提示词与说明同步**：系统提示、模式说明和设置里的模式提示都改成了「只有风险动作先问」。

### 🔒 只读：写操作工具根本不发

- 只读回合不再收到任何写操作工具的参数 schema：不点击、不输入、不跳转、不滚动、不执行脚本、不建技能和定时任务，提示词也随之变小。
- **补上一个漏洞**：把已保存的凭据填入页面（`get_secret`）现在被当作写操作，只读模式不再提供、也不允许执行。
- **`load_tools` 只列能读的组**：只读下只提供 `tabs`、`data`、`skills`、`ops`、`delegate`，不再让模型去加载那些模式里根本拿不到的工具组。

### 💸 专项工具按组按需加载

- 表单控件、滚动、按键、视觉识别与脚本这些专项页面工具改为**按需分组加载**，不再每轮都随请求发送：全自动首轮工具 schema 从 19,863 字符降到约 12,400 字符（约 −37%）。
- 模型误用一个还没加载的工具也不会失败：后台会自动加载对应分组并让它立刻重试；`run_plan` 里的步骤照常可用。
- 设置 → 工具列表按**加载分组**分节展示，一眼看清「什么时候加载什么」。

### ⏹ 从卡片直接终止运行

- 工作流或定时任务运行时，卡片会显示**运行中**，并把**立即运行**换成**终止**，一次停掉该项所有进行中的运行；历史标签的活动板使用同一份实时状态。
- 运行期间终止按钮始终可点，不会因为按钮状态互相干扰而变成「看得见点不动」。

### 🗂 设置：目录定位与安装信息

- **下载文件夹**可一键定位：在系统文件管理器里打开已配置的目录；另有入口直接打开浏览器的默认下载文件夹。
- **安装信息**卡片展示版本、安装类型（未打包/商店版）、扩展 ID 以及打开扩展 `chrome://extensions` 卡片的链接；未打包安装还能直接打开源码目录。

### 🛍 工作流广场：多个团队仓库

- 团队仓库不再只能连一个：设置里可以连接任意多个私有仓库，每个连接用自己的 classic 令牌（团队常在不同 GitHub 账号下）。
- 广场的团队视图会合并所有仓库，连接多个时提供来源筛选；某仓库加载失败只丢它自己的卡片，并在顶部提示。
- 发布时可选择公共广场或任一已连接仓库，弹窗会回到上次发布的目标，草稿按目标分别保存；旧版本的连接继续可用并在下次修改时迁移。
- **重新发布不再报冲突**：更新 listing 时补上已有文件的 `sha` 并清理多余文件，同作者再次发布就是一次正常的更新 PR；已安装的旧版本会显示「更新」按钮。
- **在面板里直接反馈**：设置末尾可写报告、附带版本/构建/浏览器诊断，直接创建公开 GitHub issue（与广场共用 classic 令牌，没有时可在弹窗里连接）。

### ✨ 界面细节

- 面板顶部通知都可以关闭。
- 「添加工作流」菜单改为点击打开。
- while 循环的条件编辑器对齐 Automa：整行高亮的触发栏、AND 轨、OR 分隔，值输入框并排；条件块的「添加路径」改为高亮主操作，下面是普通路径列表。
- 日志数据工作流改为从统一下拉框选择，不再手填 id。
- 历史记录里的截断内容和 token 名称支持悬停查看；token 看板显示工作流名称而不是 id。
- 算子节点的标题显示算子名称，而不是内部 id。

## English summary

**v0.6.16** is about spending fewer tokens and interrupting you less.
Semi-auto no longer asks before every page-changing action: it asks only for
payments/orders, passwords and verification codes (including filling a saved
credential), deletions/resets, sending/publishing, page scripts, and creating a
skill or scheduled task. Reads, screenshots, scrolling, waiting, navigation,
tab bookkeeping, saving a file and a click or fill with a recognisable
accessible name run immediately; an element the assistant cannot identify is
treated as risky and asks rather than guessing, and a `run_plan` with any risky
step asks once for the whole plan. Read-only mode now withholds every write
tool, which also closed the hole that let it fill a saved credential with
`get_secret`, and its `load_tools` only offers groups that contain something
readable. Specialised page tools (form controls, scrolling, keys, vision,
scripts) load by group on demand: full auto's first-round tool schemas dropped
from 19,863 to about 12,400 characters, and a stray call auto-loads its group
and is retried. A running workflow or task card swaps **Run now** for
**Terminate**; Settings gained folder shortcuts (open the download folder, open
the default Downloads folder) and an installation card (version, install type,
extension ID, extension page, source folder for unpacked installs) and lists
tool switches by loading group. The marketplace supports several team
repositories at once, republishing updates a listing instead of failing as a
conflict, and feedback can create a GitHub issue from Settings. Notices are
dismissible, the add-workflow menu opens on click, the while-loop condition
builder matches Automa, and operator nodes show the operator name.

- **Semi-auto**: only risky actions ask — payments, credentials, destructive
  actions, sending, scripts, persistent writes, and unidentifiable element
  targets. Reads and scrolling never ask.
- **Read-only**: no write tool is sent at all; `get_secret` is classified as an
  action and withheld; `load_tools` only lists readable groups.
- **On-demand tool groups**: round one is about a third smaller; a stray call
  auto-loads its group and asks for an immediate retry; `run_plan` still drives
  grouped tools.
- **Running cards**: **Run now** becomes **Terminate**, which cancels every live
  run of that item.
- **Settings**: folder locate actions, an installation card, and tool switches
  grouped by loading group.
- **Marketplace**: multiple team repositories, per-target drafts, conflict-free
  republishing, and in-panel feedback issues.
- **UI**: dismissible notices, click-opened add-workflow menu, Automa-aligned
  while-loop condition editor, a workflow dropdown for log data, hover details
  in history, workflow names on the token board, and operator names as node
  titles.
