>
> - `browser-copilot-0.6.18-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js）。

## ⚡ 点击目标找不到时不再白等 5 秒

- 保存时「等待元素」处于关闭状态的点击节点，数据里仍带着默认的
  `waitSelectorTimeout: 5000`。运行时强制开启等待后又沿用了这个**休眠值**，
  导致一次找不到目标的点击要轮询 5 秒；前面的可操作性预检再叠加 1.2 秒——
  一条真实运行记录里，这个点击节点耗时 **6440ms** 才报错。
- 现在强制等待改用运行时默认的 **2 秒**；保存时写入的默认等待也同步为 2 秒。
- 预检发现目标缺失、且节点已经带内核等待时**立即返回**，不再把 1.2 秒预算
  叠在真正的等待前面。
- 已经显式开启「等待元素」的节点保留自己的超时；元素当场命中的点击不受影响。
- 权衡：需要 3～5 秒才渲染出来的页面，请在该节点显式开启「等待元素」并保留
  自定义超时（例如 5000），或调高工作流的 `defaultWaitMs`。
- 提示：如果选择器本身已经失效（页面改版、未登录、进错路由），更快失败之后
  仍需要在当前页面上重新拾取元素——速度快了不等于步骤能跑通。

## English summary

**v0.6.18** makes a missed click fail at the speed the runtime promises.

- A click whose "wait for element" was off still carried a dormant
  `waitSelectorTimeout: 5000`. The forced runtime wait reused it, so an unmatched
  click polled 5 s; the actionability pre-check added another 1.2 s (a recorded
  run measured **6440 ms** before the error).
- The forced wait now writes the 2-second runtime default, the save-time
  persisted wait matches it, and the pre-check returns immediately when the
  target is missing and the kernel is already polling it.
- Nodes that explicitly enabled the wait keep their own timeout, and clicks
  whose element is already present are unaffected.
- Trade-off: a page that needs 3–5 seconds to render should enable the wait on
  that node (or raise the workflow's `defaultWaitMs`).
- A selector that no longer matches still has to be re-picked; failing faster
  does not make a broken step work.
