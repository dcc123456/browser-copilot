# v0.6.19 更新说明（自 v0.6.18 以来 / Changelog since v0.6.18）

> 本次提供**三种安装包**，按需下载：
>
> - `browser-copilot-0.6.19-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js）。
> - `browser-copilot-0.6.19-no-ocr.zip` —— **Chrome 精简版**：不含 OCR 引擎，其余功能一致。
> - `browser-copilot-0.6.19-firefox.xpi` —— **Firefox 版**（需 Firefox 128+），功能与精简版一致。
>
> Three packages ship: the two Chrome builds (full OCR and lite) plus the
> Firefox 128+ build. All are built from the same sources.
>
> **Firefox 安装**：`about:debugging#/runtime/this-firefox` →「临时载入附加组件」选择 `.xpi`
> （所有 Firefox 128+）；长期使用见 README。
>
> **Firefox**: use "Load Temporary Add-on" in `about:debugging`; a permanent
> install needs Developer Edition / Nightly / ESR with signature enforcement off.

## 💬 编辑器 AI 助手：每个工作流一份独立会话

- 助手不再共用一条会话：打开某个工作流的编辑器，历史就是这条工作流自己的；切换到另一个
  工作流不会串进同一串对话。会话随工作流删除一起清理。
- **中断的回合终于留下痕迹。** 以前整段记录只在回合结束时才落盘，service worker 被杀、
  页面崩溃或扩展重载时，第一条被中断的会话在历史里只是一个空壳。现在首个用户轮之后立即
  写入一次，之后每 5 秒续写，回合结束再收尾。
- 助手可以读**最近一次运行日志**了：编辑器底部的开关会把这条工作流最新的已完成运行随请求
  发出，模型据此定位是哪一个步骤出了问题，不需要你再手述一遍。

## 🗑 运行日志：能删、能复制、也不再撑爆内存

- 编辑器日志面板每一行都有**删除**按钮，勾选后批量条支持全选/删除所选；正在运行的行保持
  只读，否则引擎会把它写回存储。
- 整份日志可**复制为文本**（含步骤与变量），运行检查器里也能单独复制某一个变量的值。
- 变量查看器改为可读、可重置、可展开；`/` 变量菜单不再被块弹窗盖住。
- 体积收敛：调试模式以前每个节点都存一份完整变量袋，30 次历史运行把 data URL 复制了三份，
  每次 800ms 轮询都重新克隆一遍。现在只保留步骤级副本，超长字符串与超大变量袋截断，
  单次运行最多 500 步，除最近 3 次之外的已完成运行不再保留变量。

## ▶️ 运行中：启动按钮直接变成终止按钮

- 运行还在进行时，编辑器的 **Run** 按钮位置换成 **Stop**（工作流标签同理），点一下即中止本次
  运行，不需要先去找别的入口；运行结束后按钮恢复成启动。

## 🔢 参数化工作流：跑之前问一次，或者干脆不问

- 带「参数提示（parameter-prompt）」触发节点的工作流，手动或从面板启动时会弹出**运行参数
  对话框**：字段按声明预填，密钥不会出现在页面与日志里，超时后按默认值继续。无人值守宿主
  （Runner、定时任务、触发器）保持原来的静默解析。
- 参数值还能**存在工作流上**：工作流标签的行操作与编辑器工具条共用同一个对话框，保存后
  下一次运行直接带入，对话框不再打扰——定时与手动运行因此都能无人值守跑完。留空的字段
  仍会提示，密钥永不落盘。

## 🧪 脚本节点：产物怎么交给下一步，终于写清楚了

- 指南以前教模型在 `javascript-code` 里读 `vars.xxx` / `refData`——这两个全局并不存在，
  生成的脚本第一步就抛错。现在指南与工具 schema 都写清了真实的五个入参
  （`variables`、`automaNextBlock`、`automaSetVariable`、`automaRefData`、`automaResetTimeout`）。
- `return` / 裸表达式 / `automaNextBlock()` 只填 `{{lastResult}}`；后面的节点读的是**具名变量**。
  所以脚本块新增 `outputVariables` 声明：助手提交的建议会自动回填，编辑器据此把脚本节点
  算作变量生产者——`/` 菜单从此会给出脚本里写的名字，完整性校验也不再误报悬空引用。
- 脚本注入失败现在报**真正的原因**：以前页面桥的错误被丢弃，一律落到 MV3 本地 eval 兜底并
  显示它的 CSP 报错；焦点窗口是内部页面时也会自动改用其他可注入的标签页。

## 🩺 生成与变量类型的一组修复

- `set-variable` 复制对象不再变成 `[object Object]`：单 token 引用保留原始类型，
  `{{copy.a1}}` 这样的点号读取恢复可用；行定义的变量也算作生产者。
- Webhook 的 JSON 请求体由执行器自己按 JSON 上下文插值：值位置的 token 保留类型，
  字符串里的 token 做 JSON 转义，带引号或换行的值不再破坏整份 JSON。
- 助手教的 `data-mapping` 参数名与表单、执行器真正读取的键对齐（`dataSource` /
  `varSourceName` / `sources`），不再宣传形同虚设的 `mapping` 表达式。
- 编号形式的算子 id（`12. click`）能被正确读回；模型返回结构松散时照旧落地，拒绝原因也会
  如实命名；生成草稿过不了 producer 门时，通知里多了**仍然保存**，并把静态发现记成
  `saveWarnings`——保存不再被校验意见阻断，编辑器与 AI 调试仍是修复入口。

## 🧭 面板改版与设置精简

- **飞书集成**面板重排成两个分组（主动通知 / 接收指令），状态提示就地在面板内显示，
  App Secret 默认打码并可勾选查看，连接中/断开中的按钮文案与实际操作一致。
- **历史保留上限**：设置里可按区块配置最多保留多少条记录（对话、工作流运行、任务运行、
  操作历史，默认 50，范围 1–500）。删除日志时按钮进入 loading 态，批量删除有进度。
- 工作流卡片上的 **AI 修复**入口已移除——它绕过修复梯自己做决定，重跑与修复请走编辑器的
  AI 调试；修复能力本身（生成校验、失败中心、MCP、调试）不受影响。
- 模型设置里的**运行时 AI 接管**与**自动修复**两个开关已删除（默认一直是关闭的）。AI 接管
  与修复仍按各自的入口工作，接管使用的模型仍可在「AI 接管模型（AI 调试）」里指定。

## English summary

**v0.6.19** is the workflow-panel release: the editor's AI assistant gets its own history,
run records become manageable, parameterized workflows can run unattended, and the script
block finally documents how its output reaches the next step.

- **Per-workflow assistant chats.** Each workflow's editor keeps its own conversation instead
  of sharing one thread, deleting a workflow cleans it up, an interrupted turn now checkpoints
  its transcript (immediately after the first user message, then every 5 s) instead of vanishing,
  and a footer switch lets the assistant read this workflow's newest finished run log as evidence.
- **Run logs.** Per-row and bulk delete (running rows stay read-only), copy the whole log as
  text, copy one variable's value, a readable/resettable/expandable variable viewer, and the `/`
  menu no longer hides behind block dialogs. Debug runs stopped cloning the entire variable bag
  per node: bulk data URLs are shed, oversized values truncated, 500 steps per run max, and
  variables dropped from finished runs except the newest three.
- **Run becomes Stop.** While a run is live, the editor's Run button turns into Stop; after
  it finishes it turns back.
- **Parameter prompts.** A workflow that declares inputs in a `parameter-prompt` trigger now asks
  for them in a run dialog (secrets never reach the page or the log; on timeout the declared
  defaults continue), and those values can be stored on the workflow itself from a shared dialog
  in the panel row action and the editor toolbar — saved values seed the run and the prompt stops
  asking, so scheduled and manual runs of a parameterized workflow go unattended. Unattended
  hosts (Runner, schedules, triggers) keep silent resolution.
- **Script nodes.** The guide used to teach `vars.xxx` / `refData`, which do not exist in the
  harness, so generated scripts threw on the first reference; both the guide and the tool schema
  now name the real five parameters. `return` / a bare expression / `automaNextBlock()` fill only
  `{{lastResult}}`, so a script block declares `outputVariables`: proposals backfill them, the
  editor counts the block as a variable producer, and the `/` menu offers the names. An injection
  failure reports its real cause instead of the MV3 fallback's CSP error.
- **Generation fixes.** `set-variable` keeps object types (no more `[object Object]`, dotted reads
  resolve), a webhook JSON body interpolates with JSON context, the `data-mapping` schema names
  the keys the form and executor actually read, numbered operator ids parse back, loosely shaped
  answers still land, and a draft that fails the producer gate offers "Save anyway" with the
  findings recorded as `saveWarnings`.
- **Panel and settings.** The Feishu integration panel is regrouped into two cards with in-panel
  status, a masked secret field and honest in-flight button labels; retention caps per history
  section (default 50, 1–500) plus a loading state while deleting; the AI repair entry is gone
  from workflow cards (use the editor's AI debug); the two default-off run-time takeover and
  auto-repair switches were deleted from Settings → Models — the takeover engine and its model
  picker are unchanged.
