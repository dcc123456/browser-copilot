## 🛑 对着同一处反复空转的回合，现在会被叫停

- 以前对话循环只数轮次，唯一的重复守卫只认两类"重试也没用"的错误。可真正烧钱的空转是
  **成功但什么都没变**：同一个没变化的页面反复快照、点了没反应的按钮返回"未跳转、refs 仍有效"、
  一直超时——这些一次都不计数，模型可以合法地把整段预算花在原地打转。
- 现在每个页面动作之后都会采一次**页面状态签名**（新增内核算子 `progress_signature`，扩展与
  Runner 两侧同步），并跑一条纯判定：
  - **连续 3 次**结果不变 → 提醒模型换方法（这条提醒以 `[[agent-note]]` 形式给模型看，
    面板、历史、回放都会把它过滤掉，不会冒充你说的话）；
  - **再连续到 6 次** → 只拒绝**这一次一模一样的调用**，换参数、换工具照常执行；
  - 页面状态**读不到**时（PDF、`script-src 'none'` 的站点、`chrome://`、受限 iframe），
    只有在 **URL 也没变**的情况下才计数——所以"读不到页面状态"不会把动作本身已经成功的任务误杀。
- **不可逆动作单独加栅栏**：提交 / 支付 / 发布 / 发送这类动作，同样的参数第二次出现时**在派发前**
  就被拒绝，并让模型去汇报卡点，而不是再点一次。
- **恢复会话时不再重灌历史**：目标、已完成步骤、已执行过的不可逆动作指纹、已花 token 会折进
  系统提示，续跑时模型知道"哪些做过了、哪些绝对不能重放"。

## 📜 你保存的对话，永远是原文

- 以前"回收旧的页面读取""硬截断超长历史""压缩上下文"都会**就地改写**历史，所以你存下来的
  对话里页面内容是"已回收"的桩，原文永久丢失；每次改写还会让缓存前缀从那里开始整段重新计费。
- 现在这三件事都变成**请求投影**：这一轮发什么由投影决定，**存下来的对话逐字节不变**；硬截断
  有自己的 `[context-truncated]` 标记。
- 长任务不再自我膨胀：40 轮、每轮读 12k 字符页面的场景里，没被回收的旧读取从 27 条回到 1 条，
  请求体积从约 59.6k 降到约 23.5k 字节。

## 🗜 压缩降级为"逃生路径"，不再是省 token 的手段

- 两次实测都是负收益：16 轮等价成本 **+8.1%**、100 轮 **+20.7%**——因为每压缩一次，整段前缀
  就要重新计费一次，而"回收旧页面读取"已经把历史压住了，压缩没有多少可回收空间。
- 所以它现在只在**请求接近上下文窗口**、或 provider 返回长度错误时触发；输入框里的
  **`/compact`** 保留（那是你主动要求的）。
- 压缩摘要会**带标记落盘**，面板 / 历史 / 回放都不会把它显示成你的发言；下一次压缩可以把它
  回收掉，不会每压缩一次就往历史里钉一条不可回收的假用户轮。

## 🔧 修掉的三处"看起来做了"

- **压缩投影算完就被丢掉**：摘要是真生成了、钱也真花了，但那个请求根本没发出去（下一轮开头
  又被重置回原历史）——现在会一直带到后续请求。
- **硬截断把改动写回了存档**：浅拷贝投影让 `hardCapHistory` 改到了共享的消息对象，刚修好的
  "落盘原文"从另一条路径漏了回来——现在只作用于投影。
- **"已压缩"误报**：面板可能在没有压缩的情况下显示已压缩。
- 顺带修掉**手动 `/compact` 的摘要冒充用户消息**：它现在带哨兵，落盘、面板、历史、回放都认得。

## 🧪 你可以自己验（不需要任何 API key）

页面是真的、点击是真的、只有模型是脚本化的：

1. `node tmp/qa-c1-probe/server.mjs`（探针页 + 本地 mock provider，127.0.0.1:5399）
2. `pnpm build`，加载 unpacked 扩展，设置里新增自定义 Provider：Base URL
   `http://127.0.0.1:5399/v1`、Model `mock`、API Key 随便填一个非空串
3. 打开 `/submit` 发"帮我开通年度会员，提交"，然后 `curl -s http://127.0.0.1:5399/api/report`
   —— **预期 `submitClicks: 1`**（第二次相同提交在派发前被拒）
4. 打开 `/noop` 发"翻到第 3 页" —— 面板先出现无进展提醒，最后同一个调用被拦，
   `nextClicks` 停在 7 左右，不会一路点到底

## ⚠️ 已知限制：显式预算与续期还没上线

- 面板聊天仍然是"按配置步数成批、最多十批后停止"，**没有显式的轮次预算**，也没有目标条、
  预算对话框和"续期"入口。
- 一个任务的目标会**跨消息保持 `active`**，不会自动收束——因为它要靠显式的完成声明 + 可校验
  证据才置为完成，而完成入口和续期入口是同一批未上线的工作。
- 所以本版**不能**理解为"已支持无限长任务"。这一批（显式预算 + 到点报告 + 续期 + 无人值守
  自动续期）会作为一次完整改动落地，落地前不会打 tag 发布。
