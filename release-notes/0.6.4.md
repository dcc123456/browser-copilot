> and a ~98% smaller lite build without it. Everything except local OCR is

## ✨ v0.6.4

这一版的主线是**把"能生成"变成"能信"**：生成 / 调试 / 修复 / 恢复四块拼成同一条流水线，
67 个算子逐个在真实浏览器里跑过一遍并给出结论，"缺参数就不让运行"这道硬墙也拆成了
"照常运行、报错打到日志里并点名是哪个算子"。存储那一侧的数据丢失问题同时收口。

### 🤖 生成 → 修复 → 验证成为一条流水线

- **工作流 IR 与 trace 编译器** —— 图和执行轨迹有了可分析、可改写、可再验证的中间表示，不再靠解析编辑器 JSON 字符串。
- **统一的失败分类与签名** —— 确定性的失败归类 + 稳定签名，重试、预算和修复策略第一次可以横向比较。
- **统一修复引擎** —— 修复候选的契约 / 解析 / 应用，**修复即版本**（revisioned commit，不再原地覆盖），有界策略阶梯、动态修复预算，以及"目标是否真的达成"的三层验证。
- **自主编排** —— 后台修复编排器 + 运行时适配层、带阶段与续跑的恢复协议、运行失败自动触发、工作流健康摘要。
- **UI 收成一个入口** —— 单入口 AI 修复流程吸收了零散的恢复对话框；逐节点 AI 修复可应用可回退；修复提案带 diff 与风险预览。
- **基准当作门禁** —— `pnpm bench:reliability` / `bench:workflow-generation` / `bench:workflow-repair` / `bench:debug`，基线入库可对比。

### ✅ 67 个算子逐个实机验证

面板 67 个算子（目录 63 + 自定义 4）在真实浏览器里对着专门的靶站逐条跑过，**148 条用例：142 PASS / 3 FAIL / 3 BLOCKED**（覆盖 62 个，5 个记为不可测：仅云端 / 需真实 Google 授权）。逐块结论、根因与环境限制见 `specs/2026-10-06-operator-realtest-design.md`；端口答不了的四件事（contenteditable 的受信任按键、`await` 语句体、iframe 作用域、变量读取）另在**已加载的扩展**里复验。

挖出来两个用户看得见的问题：

- **只写进文档、从未被读取的算子选项**现在真的生效。
- **互斥分支闸门会漏到没连线的那个端口**：只连了"存在时执行"时，元素不存在也照样跑了该分支——路由会退回到第一条出边。`conditions` 与 `element-exists` 现在在被判定的端口没有连线时**干净停住**（`tests/branch-fallthrough.spec.ts`）。

### 🧭 缺参数不再挡住运行，报错落到日志并点名节点

- **运行照常启动**：过去整张图一个节点没填就要 20 步一步不跑，提示只活在几秒后消失的 toast 里，日志面板连这条运行都没有记录。
- **每条发现都归责到节点**（`WorkflowRunIssue`：severity / nodeId / blockId / nodeName / param / message），日志里图级问题一行、每个缺参算子一行。
- **引擎停在坏节点之前**：前面的节点照常执行，停在它面前不触碰页面，也不会让"压根没填定位"被 readiness 轮询误报成"元素不存在"。
- **编辑器同步标红 + 一键定位**：敲字的当下就用同一条规则把节点标红（角标 tooltip 就是契约原文），日志行的「定位」按钮会关掉两层弹窗、选中并把该节点居中。

### 📄 文件、用户输入与目标核查

- **`upload-file` 算子 + 文件产物 + 用户文件选择卡片** —— 运行时可以现场要一个文件，而不是把文件烤进工作流；该算子命名它要填的变量，而不是把文件带走。
- **注入内核支持工作流 JS 表达式与文件上传**；所有注入函数体都由 `pnpm verify:injected` 静态校验自包含。
- **节点目标契约、目标检查器与认证弹窗**，外加生成期指标与"打分选择器链"的落档 —— 真正命中的那条选择器链现在会回写进节点，而不是丢掉。
- **`ask_user` 工具**（带结构化候选项）、动态 agent 工具组、编辑器支持回边（loop-back edges）。

### 🎯 目标认证读的是页面，不是计划

- 目标门改读**运行前**快照，`草稿箱(100)` 这类页面既有的数字再也不能靠巧合认证一次运行。
- 只认证本次运行真的做成立的目标行；"存在性"行对准页面真实显示的字词；每一步的承诺在**它当时站着的那个页面**上评判。
- 重放会观察页面并**带证据降级**；`pnpm selftest` 失败时打印各步骤实际记录到的字词。
- 修掉两类误读：关掉浮层不再被当成登录，编辑器模式名不再被当成发布动作。

### 🗂️ 存储：数据丢失与配置丢失收口

- **配置 / 数据分家**：配了存储目录后，用户内容只写进目录，扩展配置留在浏览器存储；目录句柄暂不可用时写入进**持久 outbox**（读侧叠加待写项与删除墓碑），恢复访问后自动排空并按条目守卫，旧值无法回灌。
- **每个 key 的写锁**（工作流、设置 / provider、技能、代理、会话、档案、密码、历史、草稿）统一到 `lib/key-lock.ts`；历史页改用 worker 命令写库，消除最后一个跨上下文竞争。
- **不再伪造默认值覆盖真配置**：目录不可读时缺失的 key 保持缺失、集合不再被种成空数组；`getSettings` 会在存储里只剩出厂默认时把真实 `settings.json` adopt 回来并写回。
- 读取缓存（5 MB 上限，会话优先淘汰）让目录不可达时面板不再显示成"空列表 = 数据丢了"；设置页会显示还有多少改动等着写入文件夹。

### 🛠️ 其它修复

- `javascript` 块在脚本返回失败信封时**报失败**，不再当作成功。
- 生成的工作流保存后**保住自己的身份**；草稿保存仍受那个写着"草稿"的开关约束。
- 无人值守重放永远有一个可写的目录。
- 算子参数在目录、编辑表单、指引与 executor 四处对齐；算子失败可见（不再吞掉），文件按设置落盘。
- 失败中心的恢复阶段文案本地化；保存卡片折叠按钮换成最小化图标。

### 🏗️ CI 与仓库卫生

- **CI 改用 corepack 安装 pnpm**（此前每个 run 都挂在这一步），全仓按 Prettier 配置格式化，`main` 上 `pnpm lint` / `pnpm format:check` 从此是可依赖的阻断门禁。
- `AGENTS.md` 增加强制等级标注（`[机检]` / `[验收]` / `[纪律]`）、复用规则与"要证据不要绿灯"的收尾自检清单。

## English summary

**v0.6.4** — the theme is turning "it can generate a workflow" into "its result can be trusted": generation, debugging, repair and recovery are now one pipeline, every operator was real-tested and judged one by one, and the pre-run gate stopped refusing whole graphs.

- **One pipeline**: a workflow IR plus a trace compiler; a single deterministic failure taxonomy with stable signatures; a unified repair engine where a fix is a revisioned commit (bounded strategy ladder, dynamic repair budget, three-layer goal-aware verification); a background orchestrator with a phases/resume recovery protocol, auto-trigger on failure and a health summary; and one AI-repair entry point in the UI with per-node apply/revert and a proposal diff + risk preview. Benchmarks (`bench:reliability`, `bench:workflow-generation`, `bench:workflow-repair`, `bench:debug`) now run against a committed baseline.
- **Operator real-test**: 67 operators driven in a real browser against a dedicated fixture site — 148 cases, **142 PASS / 3 FAIL / 3 BLOCKED** (62 covered, 5 recorded untestable). Two visible defects came out of it: options that were advertised but never read now take effect, and exclusive branch gates no longer fall through to the unwired port (previously, wiring only the "exists" port ran it even when the element was absent; `conditions` / `element-exists` now stop cleanly).
- **The run gate is non-blocking**: missing parameters no longer stop the run. Findings are node-attributable (`WorkflowRunIssue`) and written into the run log — one line per blocked node — while the engine stops _before_ that node, executing everything that can work and never touching the page with a locator-less step (which used to surface as a bogus "element not found"). The editor red-flags the same nodes as you type, and each log row has a Locate action that selects and centres the node.
- **Files and user input**: an `upload-file` block with file artifacts and a user file picker card (the block names the variable it fills), page-side JS expressions and upload in the injected kernel, node goal contracts with a goal inspector and certification modal, the scored locator chain recorded and rotated into the node, an `ask_user` tool with structured suggestions, dynamic agent tool groups, and loop-back edges in the editor.
- **Goal certification reads the page**: the gate compares against the pre-run snapshot so existing page furniture (a `草稿箱(100)` counter) can't certify a run by coincidence; only rows the run actually made true are certified; a step's promise is graded on the page it stood on; replay observes the page and degrades with evidence; a popup dismissal is no longer read as a login and a composer mode name not as a publish act.
- **Storage**: config/data split with a durable outbox instead of a staging mirror, per-key write locks in `lib/key-lock.ts`, a single writer for the history tab, read cache so an unreachable directory no longer looks like data loss, `ensureSchema` no longer fabricating defaults, and `getSettings` adopting the legacy `settings.json` back. Settings shows how many changes await the folder.
- **Fixes**: a `javascript` block fails on a returned failure envelope; a generated workflow keeps its identity through save; unattended replays always get a writable directory; operator parameters aligned across catalog / forms / guide / executors; operator failures made visible and files written where configured; recovery phase labels localized; save-card collapse glyph.
- **CI**: pnpm installed through corepack (every CI run had been dying at that step), the tracked tree brought to the Prettier config, so `pnpm lint` / `format:check` are blocking-green on `main`; `AGENTS.md` gained enforcement tags and an evidence-based closing checklist.
