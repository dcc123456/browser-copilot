# v0.6.7 更新说明（自 v0.6.6 以来 / Changelog since v0.6.6）

> 本次提供**三种安装包**，按需下载：
>
> - `browser-copilot-0.6.7-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js），工作流 **OCR 识别**算子、离线验证码识别开箱即用。
> - `browser-copilot-0.6.7-no-ocr.zip` —— **Chrome 精简版**（约小 98%）：不含 OCR 引擎与语言模型，其余功能完全一致；OCR 算子置灰不可用，图片文字仍可通过视觉模型识别（设置 → 图片识别模型）。
> - `browser-copilot-0.6.7-firefox.xpi` —— **Firefox 版**（需 Firefox 128+）：由同一套源码构建，功能与精简版一致（Firefox 无 offscreen 文档，本地 OCR 不可用）；安装方法见下方「Firefox 安装」。
>
> Three packages ship this time: the usual two Chrome builds plus a Firefox
> 128+ build, built from the same sources and feature-identical to the lite
> Chrome build (local OCR is unavailable on Firefox).
>
> **Firefox 安装**：
>
> 1. **临时试用**（所有 Firefox 128+）：地址栏打开 `about:debugging#/runtime/this-firefox`，点「临时载入附加组件」，选择下载的 `.xpi`；重启浏览器后需重新载入。
> 2. **长期使用**（开发者版 / Nightly / ESR）：`about:config` 里把 `xpinstall.signatures.required` 设为 `false`，再到 `about:addons` → 右上角齿轮 → 「从文件安装附加组件」，选择该 `.xpi`。正式版 Firefox 只接受已签名扩展。
>
> **Installing on Firefox**: open `about:debugging#/runtime/this-firefox` and use
> "Load Temporary Add-on" with the `.xpi` (temporary, works on any Firefox
> 128+). For a permanent install, use Developer Edition / Nightly / ESR with
> `xpinstall.signatures.required` disabled in `about:config`, then
> `about:addons` → gear → "Install Add-on From File". Regular Firefox only
> installs signed add-ons.

## ✨ v0.6.7

这一版把两处「差点就有」补齐了：画布上多了一个会干活的 AI 助手，修复失败后会先想明白再重试；另外补上两个标签页算子本就该有的能力，并修掉了会让整次运行永远挂住的原生弹窗。

### 🤖 画布上的 AI 助手

- 过去只有两条路：从面板拖一个算子，或在侧边栏整条流程生成——「**接着加一步并把参数填好**」这件事没人管。现在画布上有一个 AI 按钮，打开的对话会把当前对话记录连同画布结构摘要一起发给模型，模型挑中的算子**直接落到画布上**。
- 落点有两种：接在选中步骤之后，或接在主线末尾；多个算子按模型给的顺序串起来。落下的一批**一键即可撤销**。
- 每个 AI 写的节点带**紫色来源环与角标**，一眼分得清哪些是你自己接的。
- 它**不试跑、不留档**：执行与页面证据仍然只归 Run / AI Fix。
- 模型能提到的算子只有提示词里给它的那些，参数落盘前还会过一遍清洗——它够不到这个版本跑不了的块，也伪造不了来源标记。
- 复用 AI Fix 已经验证过的一次性命令通道，不新增传输层、Agent 循环、端口或存储。

### 🪞 修复失败后，先复盘再重试

- 一轮修复跑完还是失败，下一轮此前**和第一轮毫无区别**：阶梯换了个策略，却把失败候选已经学到的东西全丢了，提示词里连一点页面证据都没有，于是模型把刚猜错的选择器再猜一遍。
- 现在复盘是一次独立的模型调用，它的证据是**失败重放之后那一刻的实时页面**——失败现场本身。
- 复盘可以提议换策略，但只是提议：它受与阶梯相同的**安全、预算与死胡同规则**约束，能改道，不会成为绕过策略闸门的后门。
- 复盘拿不到、被弄坏或直接抛错，一律降级为「没有复盘」，循环行为与从前完全一致。

### 🏷️ 两个标签页算子终于名副其实

- **`reload-tab` 多了一个可选 URL**：填了就替换标签页地址并加载，不填就照旧刷新当前页。这个字段与 `open-url` 共用同一份实现，协议守卫与「一次导航，不 goto 加 reload」只有一处行为。
- **`new-tab` 的「更新此前打开的标签页」复选框**此前只有目录 key 和中英文案，**没有任何执行器读它**——这也正是它被排除在模型 schema 外的原因。现在它按 Automa 的 `prevnewTabId` 语义工作：每个 `new-tab` 记下自己落到的标签页，之后一个要求复用的块会回到那个标签页，而不是再叠一个。中间被关掉的标签页则退回新建。
- 两处行为在**扩展与 Runner 两侧都做了镜像实现**（`chrome.tabs` 与 Playwright），各自带测试。

### 🛠️ 修复

- **原生弹窗不再让运行永久挂死**：页面的 `alert`/`confirm`/`prompt` 会卡住渲染进程的 JS 线程，于是点了会弹窗的那一步永远不结束，整次运行**没有任何报错**地停在那里。现在 CDP 监控会接管 `javascriptDialogOpening`（alert/confirm/prompt 一律接受，beforeunload 一律关掉），并且对没有调试器附加的标签页，给每个注入操作兜一个 30 秒的注入超时。
- **变量插值后的重复协议头**：`new-tab` 用「协议下拉 + `{{变量}}`」拼地址时，变量里存的是完整 URL 就会插出 `http://http://host//path`，浏览器把它解析成主机名 `http`、端口为空。现在导航前会先折叠掉重复的协议头，完整 URL 与只给主机名都能用。
- **数据源的配置与凭证改在弹窗里编辑**：行内编辑卡片在输入时把列表顶来顶去。现在新建/编辑都走共用的 FormDialog（与技能、任务编辑器同一套划分），保存按钮按必填项启用，保存失败的信息显示在弹窗内部，不会被遮罩盖住。
- 顺手清掉了托管包管理器列表里的 `@pnpm/exe`。

## English summary

**v0.6.7** — the workflow canvas gains an AI assistant that lands operators where you want them, a failed repair round now thinks before it retries, two tab blocks do what their labels always claimed, and a native dialog can no longer hang a run forever.

- **AI operator assistant on the canvas**: a round AI button opens a chat dock that sends the transcript plus a digest of the current graph, then lands the operators the model picks directly on the canvas — spliced after the selected step, or after the end of the main line, chained in the proposed order. A landed batch is one click from removal, and every AI-authored node keeps a violet provenance ring and badge. It neither trials a run nor stores a transcript; execution and page evidence stay with Run / AI Fix. The model may only name operators from the offer in its own prompt, and its parameters are sanitized before landing, so it cannot reach a block this build cannot run or forge the provenance marker.
- **Repair reflects before retrying**: the ladder advanced a strategy while dropping everything the failed candidate had learned, and the next prompt carried no page evidence at all — so the model re-guessed selectors it had already guessed wrong. Reflection is now a separate model call whose evidence is a live inspection of the page as it stands _after_ the failed replay. It may propose a different strategy, but only as a proposal: the same safety, budget and dead-end rules the ladder obeys hold it to. An unavailable, mangled or thrown reflection degrades to null and the loop behaves exactly as before.
- **`reload-tab` takes a URL** (replace the address and load it; empty keeps reloading in place), sharing `navigateRunTab` with `open-url` so the scheme guard and the "one navigation, never goto plus reload" rule are one implementation.
- **`new-tab` reuses a tab it opened earlier**: the "update previously opened tab" checkbox existed with its catalog key and both locales, but no executor read it. It now follows Automa's `prevnewTabId` — each `new-tab` records the tab it landed on and a later one that asks to reuse goes back there instead of stacking another. Both drivers gained the behaviour on the mirrored side as well, each with its own tests.
- **Native dialogs no longer hang the run**: an `alert`/`confirm`/`prompt` parks the renderer's JS thread, so a step whose handler alerted never settled and the run hung with no error. The CDP monitor now enables the Page domain and answers `javascriptDialogOpening` (accepting alert/confirm/prompt, dismissing beforeunload), and `execOnActiveTab` backstops every injected operation with a 30s injection timeout for tabs without a debugger.
- **Doubled URL scheme after interpolation**: a `new-tab` URL assembled as protocol dropdown + `{{variable}}` became `http://http://host//path` when the variable held a full URL, parsed as host `http` with an empty port. The doubled scheme is now collapsed before navigation, so full-URL and host-only variables both work.
- **Data-tab profiles and credentials edit in dialogs**: create/edit moved out of inline cards that pushed the list around, into the shared FormDialog with required-field gating and in-dialog save errors.
