# v0.6.9 更新说明（自 v0.6.8 以来 / Changelog since v0.6.8）

> 本次提供**三种安装包**，按需下载：
>
> - `browser-copilot-0.6.9-ocr.zip` —— **Chrome 完整版**：内置本地 OCR（Tesseract.js），工作流 **OCR 识别**算子、离线验证码识别开箱即用。
> - `browser-copilot-0.6.9-no-ocr.zip` —— **Chrome 精简版**（约小 98%）：不含 OCR 引擎与语言模型，其余功能完全一致；OCR 算子置灰不可用，图片文字仍可通过视觉模型识别（设置 → 图片识别模型）。
> - `browser-copilot-0.6.9-firefox.xpi` —— **Firefox 版**（需 Firefox 128+）：由同一套源码构建，功能与精简版一致（Firefox 无 offscreen 文档，本地 OCR 不可用）；安装方法见下方「Firefox 安装」。
>
> Three packages ship this time: the usual two Chrome builds plus a Firefox
> 128+ build, built from the same sources and feature-identical to the lite
> Chrome build (local OCR is unavailable on Firefox).
>
> **Firefox 安装**：
>
> 1. **临时试用**（所有 Firefox 128+）：地址栏打开 `about:debugging#/runtime/this-firefox`，点「临时载入附加组件」，选择下载的 `.xpi`；重启浏览器后需重新载入。
> 2. **长期使用**（开发者版 / Nightly / ESR）：`about:config` 里把 `xpinstall.signatures.required` 设为 `false`，再到 `about:addons` → 右上角齿轮 → 「从文件安装附加组件」，选择该 `.xpi`。正式版 Firefox 只接受已签名扩展。
>
> **Installing on Firefox**: open `about:debugging#/runtime/this-firefox` and use
> "Load Temporary Add-on" with the `.xpi` (temporary, works on any Firefox
> 128+). For a permanent install, use Developer Edition / Nightly / ESR with
> `xpinstall.signatures.required` disabled in `about:config`, then
> `about:addons` → gear → "Install Add-on From File". Regular Firefox only
> installs signed add-ons.

## ✨ v0.6.9

这一版的主线是**对齐 Automa、把编辑器讲清楚**。循环、Webhook、多触发器与断点调试补齐了控制流缺口；工作流变量引用支持数组与对象取值（`{{rows[0].name}}`）；编辑器助手能把模型的思考过程留在屏幕上，并且能落到全部 60 个可写算子；官方算子手册以双语 63 个算子的形式发布到文档站点。此外还修了若干真实运行问题：关闭标签页关错页面、误命名为 `.xlsx` 的文本导出解析失败、文件路径里的变量引用、以及静默中断的助手请求。

### 🔁 控制流与算子对齐 Automa

- 新增 / 对齐 **While 循环**、**Repeat Task**、**Loop Elements**；`loop-data` / `loop-elements` 改为**单一输出**，循环后的路径由「循环断点」拥有，旧的 `output-2` 图在加载/保存时自动迁移为线性结构，遗留边仍作为兜底。
- 新增 **Webhook**、**多触发器** 与**断点调试**：断点（`$breakpoint`）只在 Testing 模式暂停，暂停点、变量快照与继续/停止都走现有的调试条。
- **Set Variable** 一个节点可同时写多个变量。
- 触发器与 Webhook 的公共逻辑抽到共享层，扩展与 Runner 使用同一份实现。
- 编辑器侧栏收敛为工作流身份与算子搜索；算子面板与日志弹窗加宽；`upload-file` 的来源改为下拉选择；块字段支持弹窗编辑；算子说明词表同步更新。

### 🧠 编辑器助手：看得见的思考、完整的算子、可编辑的拾取

- 模型输出以**流式**回传：等待行显示「思考中」，推理（浅色）与正文（正常色）分通道渲染；回答结束后原始文本收进「模型输出」折叠区。思考强度会随请求发送，并在编辑器中标注模型无法表达该级别。
- 助手可写算子扩展到**全部 60 个**（触发器、代理、浏览器事件除外），提示词从 7.5k 字符增至 13k 而不是 34k。
- 在页面上手动拾取的元素现在只是**附件**：可编辑、可删除，带定位策略与选择器；发送时按步骤顺序补齐空位，缺项时不落地，未被使用的拾取留到下一条消息。
- 没带来任何参数变化的编辑会被拒绝为 `no-change`（不写撤销历史、不弹成功提示、不动认证状态）；真正落地的编辑逐项列出「旧值 → 新值」（敏感参数打码），换算子会同时列出两个算子。
- 新增一个 **新对话** 按钮：清空记录并递增代号，正在路上的回复不会落进新会话；输入框顶部加了拖拽/方向键调整高度的把手（52–240 px）。
- 用户手动修改节点后清除 **AI 来源角标**：它回答的是「这步是不是助手放上去的」，不是「助手有没有碰过」。
- 助手请求的**静默超时**：只有 120 秒没有任何正文/推理增量才会中断，每次重试重新计时，最多重试 10 次、间隔 10 秒并续写已有回答；用户取消仍然立即结束。

### 🎯 目标、变量与文件

- 新增 **Goal 目标编辑器**：可视化编辑 `settings.goalSpec` 的摘要与成功条件，保留终端状态条件，必须填完整一行才能保存；删除需要二次确认并关闭 L3 校验，任何修改都会把工作流标记为未认证。
- 变量引用支持**数组与对象访问**：`{{rows[0].name}}`、`{{obj["key"]}}` 等按「根变量 + 访问器」解析；保存时校验、来源追踪、修复策略与任务串联共用同一套解析规则。
- `upload-file` / `parse-excel` 的文件路径支持 `{{变量}}`：路径输入框通过 `{}` 按钮打开变量菜单，提示中说明支持变量与子目录文件。
- **最新下载**现在递归扫描已授权的下载目录，最新文件位于子目录时也能找到。
- `parse-excel` 改为**按内容识别**：命名成 `.xlsx` 的 CSV/TSV 文本导出可以直接解析，不再报「zip 容器损坏」；旧式 `.xls` 的 OLE 魔数仍会被明确拒绝，无法识别时会说明真正的原因；连续 BOM 会被剥离。

### 🐞 修复

- **关闭标签页**关闭的是工作流正在驱动的页面，而不是浏览器当前聚焦的页面；找不到标签页时不再假装成功；关闭后只在本次运行的窗口内跟随替代标签页，不会把运行带到用户的其他窗口。
- 生成时记录的就绪期望（readiness）会跟随用户后来改写的值：填充类算子改完值后不再报 `READINESS_TIMEOUT(value-committed)`。
- 调试模式和普通运行的行为口径保持一致；静默超时的错误文案不再误报为「无法连接 base URL」。

### 📚 文档

- 发布**双语 63 算子手册**（`docs/workflow` → `website/docs`）：每个算子都有分类页与稳定锚点，覆盖检查保证每个面板算子恰好被记录一次；落地页导航、页脚与专区都已加入链接。
- 编辑器属性面板与算子卡片的信息图标改为指向本项目的算子手册，中文界面自动切到 `-zh` 页面；五个自定义算子同样可跳转。
- JavaScript 代码块的**辅助函数**信息芯片逐条解释用途与时机；审计发现 `automaFetch` 并未在任何宿主实现、`automaNextBlock` 的 `insert` 参数无人使用，已删除/更正；补全列表与帮助芯片读取同一份目录，并由契约测试逐个在页面 harness、本地兜底与 Runner 中验证。

## English summary

**v0.6.9** aligns the workflow engine and editor with Automa, documents every
operator, and fixes real replay defects. Control flow gains while/repeat-task
loops, webhook and multi-trigger support, and breakpoint debugging; loop data
and loop elements now expose a single output whose after-loop path belongs to
the loop breakpoint. Variable references understand array and object access, the
editor assistant streams the model's reasoning and may write all 60 writable
operators, and the 63-operator reference ships bilingually on the docs site.

- **Automa parity**: While / Repeat Task / Loop Elements loops, webhook, multi
  triggers and breakpoint debugging (pause, variable snapshot, resume, stop).
  Loop Data and Loop Elements now have one output; the after-loop path belongs
  to the loop breakpoint, stored `output-2` graphs are migrated on load/save and
  legacy edges still run as a fallback. Set Variable writes several variables per
  node; trigger and webhook helpers are shared by the extension and the Runner.
  The sidebar now carries workflow identity and block search, the palette and
  logs modal are wider, `upload-file` picks its source in a dropdown, block
  fields can be edited in a popup, and the operator-guide vocabulary is updated.
- **Editor assistant**: model output streams back with reasoning and answer on
  separate channels and stays behind a "Model output" disclosure; thinking
  effort is sent and a level the model cannot express is named in the editor.
  The assistant may use all 60 writable operators, with the prompt growing from
  7.5k to 13k characters instead of 34k. Hand-picked elements are editable
  attachments filled into the batch in step order at send time; unused picks are
  kept for the next message. An edit that changes no parameter is refused as
  `no-change`; a landed edit lists every changed key old → new with secret values
  masked. A new-chat button clears the transcript without letting an in-flight
  reply land in it, and the composer has a drag/arrow height grip (52–240 px).
  User edits clear the AI provenance badge, which answers whether the assistant
  placed the step, not whether it ever touched it. The assistant request is now
  idle-timed: 120 s with no text or reasoning delta aborts the attempt, retries
  ten times at 10 s intervals and continues the partial answer; user cancels end
  immediately.
- **Goal, variables and files**: a Goal tab edits `settings.goalSpec` summary and
  success conditions with terminal-state rows preserved, requires a complete row
  before saving, and marks the workflow unverified on any change. Variable
  references resolve array/object access (`{{rows[0].name}}`, `{{obj["key"]}}`),
  and every save-time scanner agrees with the runtime about the root variable.
  File paths in `upload-file` / `parse-excel` accept `{{tokens}}` through a `{}`
  menu, and latest-download scans authorised download roots recursively.
  `parse-excel` detects content first, so a delimited text export named `.xlsx`
  parses instead of failing on a truncated ZIP container; OLE `.xls` magic is
  still rejected explicitly and unreadable files report the real cause.
- **Fixes**: close-tab closes the page the run drives rather than the focused
  tab, no longer reports success when there is nothing to close, and follows the
  surviving tab only inside the run's window. Stored readiness expectations
  follow a value the user later edits, ending `READINESS_TIMEOUT(value-committed)`
  on fill-type blocks. Idle-timeout failures no longer masquerade as "Cannot
  reach the base URL".
- **Docs**: a bilingual reference covers all 63 operators with category pages and
  stable anchors, guarded by a coverage check; block info icons and the
  floating assistant link to it, with the Chinese locale using the `-zh` pages.
  The JavaScript code block explains each advertised helper in en and zh-CN;
  `automaFetch` (implemented in no harness) and `automaNextBlock`'s ignored
  `insert` argument were removed or corrected, with a per-helper contract test
  across the page harness, the local fallback and the Runner.
