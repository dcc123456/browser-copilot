# 对话任务标签页上限 / Conversation tab budget

## 问题与证据

用户让全自动 Agent 搜索资料时，浏览器会不断新增标签页，最终因标签页过多而崩溃。

代码路径已经确认：`src/background/agent.ts` 的 `tab_new` 每次都调用
`src/background/driver.ts:newTab`，后者无条件 `chrome.tabs.create`。对话模式没有记录
哪些标签页由 Agent 创建，也没有数量上限；`closeTabsAtEnd` 只属于工作流运行，不覆盖普通对话。
每次用户消息都会新建 `ToolContext`，所以只把计数放在单轮上下文里仍会在多轮对话中累积。

## 方案

- 以**根对话**为单位保存一份内存台账，记录 Agent 创建的 tab id 与窗口 id；沿用
  `loadedToolGroupStore` 的 LRU 方式限制最多 64 个对话的元数据。
- `runAgentTurn` 每次重建上下文时取得同一本台账；子 Agent 通过 `AgentDeps` 继承同一引用，
  因此主 Agent 与所有子 Agent 共用预算，不能各自再开 5 个。
- 同一对话、同一窗口最多保留 **5 个 Agent 创建的标签页**。第 6 次及之后的 `tab_new`
  不再新建，而是用现有 `driver.reuseTab` 激活并导航**创建顺序最早**的那个；成功复用后仍保持
  创建顺序，后续继续复用它，而不是轮转覆盖其它结果页。
- 台账条目失效（用户手动关闭、页面关闭、窗口关闭）时，`reuseTab` 返回 null；剔除该条目后，
  若仍有 5 个条目就尝试下一个最早标签页，低于 5 个则新建一个补位。新标签页创建后立即登记，
  取消或后续观察失败也不会漏记。`open_url` 仍只导航当前标签页，不进入台账。
- 窗口 id 一并记录，避免同名默认对话在不同侧栏窗口之间互相导航标签页。内存台账在
  service worker 重启后丢失是 best-effort 限制；本次不引入持久化或全局浏览器标签页上限。
- 只复用 Agent 自己创建的标签页，绝不关闭或改写用户原有标签页。通过点击 `target="_blank"`
  链接间接打开的标签页不在本次范围内。

## 模型引导

搜索和顺序阅读默认走 `open_url`（当前标签页）；只有确实需要同时保留独立页面时才用
`tab_new`。规则放在两个工具各自的 description 中，避免与系统提示重复。`tab_new` 的结果明确
返回 `reused: true`，让模型知道当前页面是复用而非新建。

## 测试与验收

新增 `tests/agent-tab-budget.spec.ts`：

1. 前 5 次调用各创建一次，第 6 次复用最早标签页且不再创建。
2. 第 7 次仍复用同一个最早标签页，不轮转。
3. 最早标签页已关闭时剔除它并复用/新建，始终不超过 5 个有效条目。
4. 不同对话、不同窗口不共享可复用条目；同一上下文跨多次调用保留台账。
5. 创建失败不登记。

门禁：`pnpm typecheck && pnpm test && pnpm build`，另跑 lint / format / `verify:injected`。

真实浏览器验证：加载 unpacked 扩展，在全自动模式连续要求打开 7 个搜索页；预期前 5 个新建，
第 6、7 个复用最早那个，用户原有标签页不被修改，工具结果显示 `reused: true`。

2026-11-13 实证：重载当前构建后，通过真实扩展的 `run_plan` 连续执行 7 次 `tab_new`，7 步均成功，
`list_tabs` 只观察到 5 个本次创建的新标签页（原有两个标签页保持不变）；随后只关闭这 5 个测试标签页，
再次列举确认原有两个标签页仍在。跨轮与子 Agent 共享台账、第 6/7 次固定复用最早者由专项测试锁定。
