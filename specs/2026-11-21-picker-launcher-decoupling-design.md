# 取元素器与浮动按钮解耦 / Picker launcher decoupling

> **文档状态**：需求与验收标准（产品侧）。实现方案由 `世界级开发程序员` 在其 design 段补齐（§6）。
> 日期 2026-11-21。

## 1. 来源与归类

| #   | 反馈（用户原话）                                                                                           | 归类                  | 判断                                                                                                                       |
| --- | ---------------------------------------------------------------------------------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| F1  | 「点击元素选择器的十字准星按钮，导致浏览器上的元素失焦，就会使一些失焦消失的弹窗选不到，我要避免这个情况」 | 体验缺陷（真 Bug 级） | 真问题，且**不是"加一个 preventDefault"就完事**：这是「按下准星」与「picker 已打开后按下」两个阶段，现有吞事件只覆盖后者。 |
| F2  | 「十字准星按钮也要可拖动，现在是只有 logo 按钮存在的情况下才可拖动，希望它们两个是独立的，但不能重合」     | 功能缺失 + 结构问题   | 真问题。「只有 logo 在才可拖」不是 bug，是准星**寄生在浮动窗口里**的结构决定的，要拆。                                     |

## 2. 现状事实（代码级，供开发对照）

- **准星寄生在浮动窗口内**：`element-picker-launcher.ts:145` 的 `mount()` 在检测到
  `browser-copilot-floating-host` 时，把准星 host `appendChild` 进那个浮动窗口（由它的 `<slot>`
  渲染），并清掉自己的 `position/right/bottom`；没有浮动窗口时才固定在右下角。
  对接靠同步事件 `bc:floating-window-ready`（`element-picker-launcher.ts:39`、`:189`）。
  → 所以「只有 logo 在时才能拖」是**当前结构的必然结果**，不是遗漏。
- **拖动与持久化属于浮动窗口**：`floating-button.ts:23-24` 写明「拖任一按钮移动的是整个窗口」，
  落点按**窗口**持久化（`floating.move` → worker → `chrome.storage`）；按钮 40px
  （`floating-button.ts:51`），视口边距 8px（`:53`）。
- **准星按钮本身是普通 `<button>`**：`element-picker-launcher.ts:81` 创建、`:123` 只挂 `click`。
  按下时浏览器默认行为会**移动焦点**，页面上「失焦即关闭」的弹层（`focusout` / click-outside）
  因此关掉——这正是 F1。
- **picker 打开之后已经有吞按下的处理**：`element-picker/index.ts:816` 的 `swallowPress` 用
  `window` capture 阶段 `preventDefault + stopImmediatePropagation`，注释（`:811-815`）明确写了
  目标是「页面永远看不到这次 press」。**它只覆盖 picker 打开后的按下，不覆盖点准星那一下。**
- 按钮文案（title / aria-label）已双语（`element-picker-launcher.ts:66-70`）。

## 3. 用户可见变化（必须写进 release notes）

1. **准星按钮不再属于插件小窗**：最小化面板时，准星不再被塞进 logo 所在的那一个盒子；两者是
   页面上两个独立按钮，各自拖动、各自记忆位置。
2. **点准星不会再让页面失焦**：焦点在输入框、下拉展开时点准星，下拉不关，可以直接点下拉里的选项。
3. 准星的位置**第一次有了自己的记忆**：拖到哪，刷新后还在哪（以前它跟着窗口走）。

## 4. 需求

### R1（P0）按下准星不得让页面失焦

- **用户故事**：作为需要选择弹层内元素的人，我点准星时，正在编辑的输入框和刚展开的下拉必须保持原样。
- **行为要求**：
  1. 按下准星那一刻，页面**不得发生焦点转移**：`document.activeElement` 不变，
     页面上的 `blur` / `focusout` 事件计数为 0；
  2. 页面**看不到这次按下**（click-outside / mousedown 关闭类弹层不得因此关闭）；
  3. 准星按钮**不参与 tab 序**（不能 Tab 到它再触发同样的焦点转移）；
  4. 只吞**这一次** press：页面其余点击、滚动、拖动一律照常，不许变成全局事件拦截。
- **边界 / 异常**：
  - picker 已经打开时（第二段按下）行为不变，沿用现有 `swallowPress`；
  - `Esc` 取消、按钮自身的可点击性、键盘 `Enter` 提交（现有点击无关路径）必须仍然可用；
  - 弹层如果被页面**定时器**关闭（不是失焦关的），本条不承诺救回来——那是页面行为，归 §7 待验证。
- **成功反馈**：准星按下→picker 卡片出现，弹层仍在，能点中弹层里的选项。
- **失败反馈**：若某类弹层仍关闭，必须能定位是「焦点转移」还是「页面看到 press」，不得含糊成「偶发」。

### R2（P0）两个按钮独立拖动与记忆

- **用户故事**：两个按钮我想放哪放哪，互不带动，下次打开还在那。
- **行为要求**：
  1. 面板打开（**没有** logo）时准星**可以拖**；以前不能（它固定在右下角）；
  2. logo 在时，两个按钮**各自拖**，拖一个不动另一个；
  3. 各自位置**独立持久化**，刷新页面、切标签页回来位置不变；
  4. 点击与拖动的区分沿用现有阈值语义（移动小于阈值算点击，不会因为手抖而不触发选择）。
- **边界**：位置越界（窗口缩小 / 旋转 / 缩放）时夹回视口内；按钮必须始终完整可见、可点。
- **异常**：持久化读不到 / 值非法时回落到默认位置，不得把按钮渲染到视口外。

### R3（P0）两个按钮不得重合

- **用户故事**：拖到同一个位置时，不能出现一个盖住另一个、点不到的情况。
- **规则**（谁让谁必须写死，否则实现与验收各说各话）：
  1. **被拖动的那个保持用户落点**，另一个**让位**；
  2. 让位后的间距 ≥ **8px**（沿用现有视口边距量级），两个矩形不相交；
  3. 让位后仍越界或仍冲突时，把让位方夹到最近的合法位置；**任何情况下不允许重叠**；
  4. 让位只在落点那一刻计算；用户继续拖另一个时，规则重新以「被拖动的那个」为准。
- **边界**：视口极窄（宽度 < 两个按钮 + 间距）时，优先保证两个都可见，允许上下错开。

### R4（P1）结构解耦（不再是"一个盒子"）

- 准星**不再作为浮动窗口的子节点**；浮动窗口的最小化/展开、重建、重载，都不得改变准星的位置与可见性。
- 两者的层级与尺寸各自独立；删除/失效的实例清理逻辑（双方的 orphan 处理）不得互相误删。

### R5（P0）兼容与迁移

- 已有的 logo 位置（按窗口存的百分比）**继续有效**，不因本次改动丢失；
- 准星没有历史位置 → 默认停在右下角，并与 logo 做一次避让；
- **不新增第二套配置来源**：准星位置沿用现有存储体系（具体键由开发在其 design 段写明，需报备）。

### R6（P1）说明与文案

- release notes 写清 §3 的三条用户可见变化（结构解耦属于行为变更，AGENTS.md §4 要求改 README 的过时描述）；
- 新增/修改的 title、aria-label 仍中英双语（AGENTS.md §3）。

## 5. 验收标准

| 编号 | 对应需求 | 判据                                                                                                                 | 方法与类型                                                |
| ---- | -------- | -------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------- |
| AC-1 | R1       | 焦点在输入框、下拉展开时点准星：`blur` = 0、`focusout` = 0、`activeElement` 不变、下拉仍展开且**能点中下拉里的选项** | QA 探针页 `/picker-focus`；真机 Chrome；验收              |
| AC-2 | R1       | 准星按下时页面监听器**收不到**这次 press（click-outside 计数器 = 0）；页面其余点击计数正常                           | 同上，双计数器；验收                                      |
| AC-3 | R1       | 准星不可 Tab 聚焦；`Esc` 仍取消；picker 内 `Enter` 仍提交                                                            | 手工 + 探针；验收                                         |
| AC-4 | R2       | 无 logo 时可拖并持久化；刷新 / 切页回来位置不变；logo 在场时各自拖互不带动                                           | 真机；验收                                                |
| AC-5 | R3       | 两按钮矩形不相交且间距 ≥ 8px；拖到对方位置时"拖动方保持、另一方让位"；缩小视口后两者仍完整可见                       | 探针读 `getBoundingClientRect`；门禁可单测计算函数 + 真机 |

| AC-7 | R5       | 旧 logo 位置保留；准星无历史位置时落到右下角并避让                                                                   | 真机 + 存储断言；验收                                     |
| AC-8 | R6       | README 两份与 release notes 已更新 §3 三条变化；新增文案中英双语                                                     | 文档审查；门禁（类型/文案）                               |

popover 真的关过一次），不能只跑一个永远不关的假下拉。

## 6. 实现方案（待补）

由开发补写，约束为 §4–§5。至少回答三件：① 焦点保持与事件吞没的手段与覆盖范围；
② 准星位置存哪里（沿用哪套存储、键名）；③ 避让算法的输入输出（谁让谁、边界怎么夹）。

## 7. 暂不采纳

| 想法                               | 不做的原因                                       | 未来触发条件                       |
| ---------------------------------- | ------------------------------------------------ | ---------------------------------- |
| 把准星改成浏览器工具栏 action 图标 | 那就不再是"在页面上点选"，丢掉"就近选择"的价值   | 不做                               |
| 两个按钮合并成一组可折叠的小工具条 | 用户明确要**独立**，合并等于把 F2 反向做一遍     | 不做                               |
| 给页面提供"锁定焦点"的全局开关     | 范围过大、掩盖问题，且页面各类弹层机制差异大     | 若某类页面弹层仍无法覆盖且高频出现 |
| 准星跟随滚动重新定位/吸附边缘      | 当前诉求不含此，且会让"拖到哪就在哪"的预期变复杂 | 用户提出时再评估                   |

## 8. 待验证假设

1. **弹层的关闭机制有多少种**：`focusout`、`pointerdown`/`mousedown` click-outside、定时器、
   `visibilitychange`…——R1 只承诺前两类；探针页需覆盖真实站点常见的那几种，结论回填本文档。
2. **遮罩层与 `inert`**：某些站点的弹层会给页面其余部分加遮罩或 `inert`，准星是否仍可点？
   需要在真机上验一次，必要时调整标题层级。
3. **iframe 场景**：准星只注入 http(s) 顶层与允许的 frame，弹层在跨域 iframe 内时本能力不覆盖，
   需在 README 已知限制里说明一句。
