## 2. 现状事实（代码级）

- **只有"选中 → 就地改"一条路**：`App.tsx:1772-1776` 的 `applyNodeActionFromAi` 在
  `targetNodeId` 为空时直接返回 `problem: 'no-selection'`；注释原文写的是「The target is always the
  editor's own selection. Without one there is nothing to change in place, and the assistant must not
  guess.」→ 用户被要求"先选中第 10 步"就是这条的直接产物。
- **模型不能命名节点**：`OperatorAction` 只有 `append / prepend / edit / replace`
  （`operator-advise.ts:110-117`），且注释明确「The target of prepend/edit/replace is always the
  editor's own selection — the model never names a node」。`prepend` 更是必须有一个选中的节点作"前面"。
- **摘要只覆盖线性主链**：`operatorDigestOf`（`operator-advise.ts:1352`）按 `chainOrderOf` 输出
  序号 + blockId + 标量参数（截断 160）+ 产出变量 + `<< selected` 标记。它**不输出分支、循环回边、
  错误分支**（这些在图里由 `normalOutgoing` / `loopBackEdgeIds` 单独处理）——所以模型看到的是一串
  直线，不是一张有分叉的图。
- **撤销已有但只有一层**：AI 改动走 `aiUndoRef`（`kind: 'node' | 'chain'`），能撤销**最近一次** AI 批量；
  不是多步历史。
- 结构校验/端口权威已存在（`applyOperatorAction`、`prune`、`missing` 等返回 `problem/problems`），
  这是本次可以复用的地基——问题不在"改不改得对"，在"能不能定位到要改的位置"。

## 3. 问题定义

- 用户要的是**结构性改动**（在 A 之后、B 之前插入；移动；删除并重连），而现有入口只接受
  **就地改动**（改一个已存在的节点）。
- 用"请先选中"把定位责任推给用户，等价于要求用户先替 AI 完成一半工作。**位置必须是参数，不是选中态。**
- 但同时不能放任："让 AI 自由重排整张图"会让一次回答的破坏面不可控——所以这次只放开
  **显式、可校验、可撤销的结构操作**，不做自由重写。

## 4. 需求

### R1（P0）读全图，不依赖选中

- 助手每次回答前拿到的图摘要必须包含：**节点 id**、类型、参数、产出/消费变量，以及
  **拓扑**——主链顺序、分支、循环回边、错误分支各自连到哪。
- **每个节点必须带上"它能看见哪些变量"**（2026-11-22 新增，来自一次真实失败）：loop 内可见
  `{{loopItem}}`、loop 外不可见；哪些变量由上游产出、哪些来自 trigger/参数。**模型分不清作用域，
  就会给出"结构合法、语义错位"的方案**——这比多插几个节点重要得多。
- 空图、单节点图、只有错误分支的图都是合法输入，摘要不得为空模板或报错。
- 摘要里点明"当前选中"仅为便利，**不是**改动前提。

### R2（P0）任意节点定位

- 结构操作的入参必须带显式节点标识（如 `targetNodeId`），**不要求用户先在画布上选中它**。
- 目标不存在/已删除时，必须明确拒绝并说明是哪个 id 失效，不得猜一个"最像的"节点。
- 用户选了节点时，该选中可作为**默认值**，但 AI 可以显式指定别的节点覆盖它。

### R3（P0）四种结构操作

1. **insert-after**：在指定节点之后、其原后继之前插入一段（自动重连两条边）；
2. **insert-before**：在指定节点之前插入（等价于在它的入边中间插入）；
3. **move**：把节点 X 移到 Y 之后（或指定位置），保持执行语义不倒退；
4. **delete + reconnect**：删除节点 X，把它的前驱直接接到它的后继；
   以及沿用现有 `edit / replace`（就地改）。

- 每次操作必须能一次表达"插入一段链"（用户场景是一次插入一个去重节点，但批量插入同样常见）。
- **边界**：目标节点是循环体入口/出口、分支端点时，插入位置必须明确落在循环内还是循环外——
  由 AI 在回答里说明，并在 diff 里可见。
- **`move` / `delete` 的静态引用检查（P0，2026-11-22 补）**：这两类操作会把**生产者**搬走或删掉，
  而下游可能还在引用它的产出（如 `{{noteIds}}`）。落地前必须扫一遍下游引用：
  **凡是引用了"没有生产者"的变量，要么整条拒绝（`dangling-reference`，点名哪个节点引用了哪个变量），
  要么给出明确警告——不许静默放行**。理由：等到运行到那一步才失败太晚，用户已经在等结果了；
  这和第一次"结构合法、语义错位"是同一个病的另一半。
- **入口保护**：入口（trigger）不可移动、不可删除；把节点移到自己下游按 `move-cycle` 拒绝，不写半截。

### R4（P0）原子性与回滚

- 一次改动**要么全部落到画布，要么一点不动**；任何一步校验失败（端口不匹配、缺必填参数、
  变量未定义、形成非法环）都要整体拒绝，并把失败原因逐条列出。
- **不允许"改了一半"**：现有 `problem` 返回必须扩展成"整批失败"，不能只跳过失败的那一段而落盘其余。

### R5（P0）改动可见 + 一次撤销

- 改动落地前展示**可视 diff**：新增/删除/移动了哪些节点、哪些边被重接、哪些变量引用受影响。
- 落地后提供**一次撤销**，把整批改回原状（多步历史可以不做，但"整批回滚"必须有）。

### R6（P0）运行时语义不被打断（两条引擎硬约束 + 持久层指名）

**引擎硬约束（2026-11-22，开发读代码确认；改写方案前必须按这个）**：

1. **loop body 由 loop 节点的 `output-1` 边决定；loop 的出口由 `loop-breakpoint` 的出边决定**
   （旧 `output-2` / `end` 仅作 legacy 兜底）。
2. 因此 `insert` 的合法位置只有三种：**loop 之前**、**loop 与 body 之间**、**body 之内**；
   **插入/移动不得把 `loop-breakpoint` 挪出 body**——挪出去 body 就没有出口，循环体不执行或直接断流。

**持久层指名（P0，2026-11-22 裁定）**：去重与累积依赖的那份"历史"必须**跨运行持久**，并在方案里
**点名是哪一层**：

| 层                                                    | 能不能用 | 原因                                                                                                   |
| ----------------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------ |
| run 变量（`ctx.variables` / `{{commentedNotesCsv}}`） | **不能** | 变量是**单次 run 的**，从 trigger/参数种子初始化，checkpoint 只为断点续跑保存；不可能跨 run 自己往上长 |
| 页面 `localStorage`                                   | **不能** | Runner 每次 run 是全新浏览器上下文，页面存储不跨 run（QA 实测：插了去重节点照样重复提交 10 次）        |
| 外部持久层（站点账号级历史 / 服务端 API / DB / 文件） | **可以** | QA 夹具改用服务端持久历史后，才是 5 次提交、0 重复                                                     |

- 验收口径：**连跑两次，第二次跑完后 CSV 里仍含第一轮的数据**（AC-8）。做不到，AI 插出来的节点就是
  "图看着对、跑起来每次从空开始"。
- **循环前改写数据源必须生效**（2026-11-22 新增，P0）：在 loop **之前**插入一个节点、改写 loop 读取的
  变量（如 `automaSetVariable('noteIds', 过滤后的数组)`），**loop 必须读到新值**。用户要的是
  「循环前过滤数组」，不是「循环内逐条跳过」——后者语义不同（每条都提交再跳过）。
  这条不成立，"在循环前插节点"就是空话。
  **引擎结论（2026-11-22，开发核实）**：`loopThrough === 'variable'` 分支在**进入循环前**执行
  `getByPath(variables, variableName)`，而 `javascript-code` 会把 `automaSetVariable` 合并进
  `ctx.variables`——所以这是**本来就有**的能力，不需要改引擎。（循环开跑后改数组不影响本次迭代列表，
  属预期。）
- AI 回答里必须说明用的是哪一层；判断不出时**明说需要用户确认**，不许默认挑一个。

### R7（P2，单独修，别混进批一）未解析变量不得当字面量提交

- 2026-11-22 实测（QA 夹具 `fixture-unresolved-var.json`）：循环外节点写 `const note = '{{loopItem}}'`
  并直接提交 → `/api/comments` 出现 `"{{loopItem}}": 1`（`total 6`），站点真的收到一条这样的评论，
  而且混在五条真实笔记里，用户很难发现。
- **根因（开发核实，`a95f742` 已修）**：不是"AI 放错位置"，而是**引擎漏了一类节点**——
  `javascript-code` 不在 `pageActing` 里，未解析 token 的守卫从来没跑到它；它的文本是**程序**，
  `{{loopItem}}` 原样留在字符串里，脚本就把花括号发出去了。现在它走同一条守卫，报错保留
  `UNRESOLVED_INPUT` 前缀（失败分类据此映射 `INVALID_PARAMETER`），并给出人话原因。
- 要求：**未解析的变量不许原样发出去**——引擎必须报错或跳过该条，并给出可读原因；站点不该收到
  一串花括号。
- 这与"AI 放错位置"是两件事：一个是提示词/digest 问题，一个是**取值兜底**问题，分开修、分开验。
- 边界：变量**合法为空**（空字符串、空数组）不算未解析；只有"引用了但解析不到"才触发。
- 真机用例（QA）：循环外节点引用 `{{loopItem}}` → 站点**不得**收到 `{{loopItem}}` 字面量；
  引擎报错或跳过该条，并给出可读原因。

| 能力        | 实现                                                                                                                                                                                           |

| diff + 撤销 | 落地只 `pushHistory()` 一次，撤销快照是**答话前的整张图**；`OperatorLanding` 新增 `kind:'graph'`（added / changed / pruned / missing 回给聊天行）                                              |

## 6. 暂不采纳

| 想法                           | 不做的原因                                         | 未来触发条件                         |
| ------------------------------ | -------------------------------------------------- | ------------------------------------ |
| 让 AI 自由重排/重写整张图      | 一次回答的破坏面不可控，diff 也没法核对            | 结构操作稳定后，再评估"批量重构"模式 |
