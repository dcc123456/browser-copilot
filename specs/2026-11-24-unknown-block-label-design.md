## 2. 现状事实

- `migrate.ts` 里对未知块的 label 规则原本是
  `label = data.description || CATALOG_BY_ID.get(blockId)?.name ?? blockId`：未知块查不到目录名，
  于是 label 被写成 blockId（或 description），**原来的 label 永远丢**。
- 占位卡片文案里有一句"若原名称与 id 不同再显示"，因此这条分支对任何经过正常保存的记录都不可达。
- `957fb07` 已让 `blockId` 与 label 在保存路径上保留原值；本次补的是 label 的迁移规则。

## 3. 需求

### R1（P0）未知块保留文件里的原名称

- 迁移时对**未知块**（目录里没有的 `blockId`）**不得改写 label**，保留文件里的原值。
- **已知块规则不变**：仍是 `description → 目录名`，行为不动。
- 占位卡片显示「未知算子：<blockId>」，**原名称与 id 不同时**追加「原名称：<label>」。

### R2（P0）不得丢数据

- 保存 / 刷新 / 迁移前后：`blockId`、label、节点参数（如 `mysteryParam: 42`）、边**全部保留**。
- 用户看到的是"这一块暂时不认识"，而不是"这一块没了"。

### R3（P1）验证必须走真实路径

- 结论必须来自**完整保存 + 刷新（触发 migrate）**后的界面与存储，不接受绕过 `workflows.save` 的探针结论。
  （本次两条假绿/空修都源于此：探针显示"原名称"，真实路径上 label 已被改写。）

## 4. 验收标准

| 编号 | 判据                                                                                                                                              | 方法                    |

| AC-1 | 写入 `label: 'Old operator'`、`blockId: 'u1: some-removed-block'` → **保存** → 卡片显示「原名称：Old operator」，存储里 label 仍是 `Old operator` | 真机（完整保存 + 刷新） |
| AC-2 | 保存 / 刷新后 `blockId`、label、`mysteryParam`、两条边**全部保留**                                                                                | 真机 + 存储断言         |

**红→绿**：AC-1 在 `538c347` 上必须红（label 被改写为 blockId，卡片无「原名称」），`9df140a` 起绿。
