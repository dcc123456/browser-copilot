## 2. 现状事实（代码级）

- `auto-layout.ts` 分层：Kahn 拓扑排完后，**剩下的环内节点按 `ids` 数组顺序直接追加**（约 149→165 行）；
  分层时对**所有**前驱取 `max(layer+1)`（约 171 行），**包括回退边**。
  → 同一张图只把节点数组反序，`n2` 从第 2 层掉到最后一列、5/7 条边向左。**数组顺序会随导入 / 生成 /
  重新保存而变**，所以用户会遇到"昨天排好的图今天排不一样"。
- 跨行折行是 Z 形：下一行从上一行起点开始，导致正向边**向左回折**。这条**与回退边无关**
  （不收回退边的对照组同样 2/6 条向左）。
- 编辑器本身能从 **`sourceHandle` 认出回退/fallback 边**——不必靠 DFS 去猜。

## 3. 产品判断

- **确定性是正确性**，不是风格：同一个输入两种输出，用户会以为图坏了、或者自己接错了线。
- ~~**正向边一律向右**~~ → **已否决（2026-11-24，用户反馈 + admin 撤回）**：阶梯式折行导致整张图
  沿斜线向下生长，用户看不到整体流程。**不能接受画布更宽的抽象结论**——要看真实编辑器截图。
- **正确方向（admin 定）**：**同一层纵向堆叠、分层按横向展开**。主线是一条横轴，条件分支展开成
  并排的支路，回退线仍只作回退、不参与分层。
- **零交叉不是目标**：追求最小交叉是 NP 难，把不可达标准写成 AC 只会逼出假绿。交叉数**只记录**。

## 4. 需求

### R1（P0）回退边必须被识别并从分层中剔除

- **按图结构判定（拓扑优先）**，不靠 `sourceHandle`：2026-11-24 实测，用户手画的回退线和普通正向边
  **用的是同一个 handle**（`javascript-code-output-1`），`-output-fallback` 只是**错误回退端口**
  （`onError → fallback`，另一种语义），分不出"把线接回前面的算子"。所以 handle 只能覆盖错误端口那一类。
- **判定方式**：强连通分量里以"有外部入边的节点"为入口排深度，只抽**真正指回上游**的边；
  `onError` fallback 端口作为**第二重**直接排除。手画回退线（无区分 handle）照样能被排除。
- 实现记录：`8df8b97` 先修回退边与确定性；最终布局为 `114b090`（分支组不可拆 + 合并主链在右 +
  长链可读），早期阶梯折行已被否决。
- 剔除后按剩余正向边分层；环内节点不得"按数组顺序追加"决定层级。

### R2（P0）排版必须确定

- **同一张图、节点与边集合相同 → 排版结果逐字节相同，与节点数组顺序无关**。
- 排序/并列时的次级比较必须用**稳定键**（如节点 id），不得依赖数组下标或插入顺序。

### R3（P0）横向主线 + 不可拆分支组 + 仅长链折行

- **分层按横向展开**：同层级节点纵向堆叠，不同层级从左到右推进。
- **条件分支是不可拆的单元**：同一条件的各支路必须作为**同一分支组**纵向排列，不得隔行；
  合并后的主链必须仍在支路右侧，不得倒挂或掉到支路下方。
- **折行粒度约束（2026-11-24，方案 C，条件化）**：
  - **有分支组的图**：折行按**整分支组**切分，**每行至少 3 列**（尾行 ≤2 列也须是"分支组完整后的剩余"），
    分支组不得跨行切碎；不足 3 列就并入相邻行。
  - **纯长链（无分支）**：**允许尾行不足 3 列**——尾行只剩 1–2 个卡片跟段落末行只有几个字一样，
    **不构成语义破坏**；硬凑行数只会把字挤小。纯长链按"让缩放最大"打包。
  - 为什么区分：`412f015` 的问题不是"折行"，而是**把 8 个节点的分支图切成 5 行、其中 4 行只有 1–2 张卡**，
    主链被迫两次向左下折回。纯长链没有分支语义可破坏，尾行短小无害。
    行与行**左对齐**（Z 形），与已批准的长链形态一致——**不允许"下一行接在上一行末尾右侧"的斜向生长**。
    若按此规则连 3 列都排不出（视口极窄），**退回单行并把间距加到能放下的最大值**：宁可间距小，也不让形态退化。
    为什么：`412f015` 数值全绿（典型图 19.5px / 58.5px）却把 7 列排成 **3 列 × 6 行阶梯**，
    主链两次向左下折回、虚线斜穿画布——**正是用户报"看不到整体流程"、已被否决的形态**。
    真正的病因不是"折行"，是"每行只放 1–2 列的碎片行"。
- **只有长链才折行**：折行点只能落在**完整分支组之后**，不得拆开分支组；小图不为了"填满视口"而折行。
- **相邻行回折已否决**（2026-11-24 admin 撤回）：它在真实分支图上仍会把条件的 yes/no 拆到不同高度，
  让合并主链倒挂。**不采用蛇形换行**——第二行从右往左会把流程读反。
- **回退线只作回退**，不参与分层，也不得被当普通换行边处理。
- **节点间距同样要保**（2026-11-24 用户反馈"算子之间间隔太小"）：**判据用屏幕像素，不用逻辑坐标**。
  - **间距优先、可读兜底**：默认按宽松档（`hGap/vGap = 40/40`）排版；**若排完字号 <9px，回退到紧凑档
    （20/36）重排一次**；两次都 <9px 才接受并记录实测值。
  - **红线：任何规模都不能比修前（`db27b86`，20/36）更差**——不能为了小图的间距把大图变成"太糊"。
  - **日志必须输出用了哪一档**（`gap: 40/40 | 20/36`），否则以后分不清是策略变了还是碰巧。
  - **根因记档**：`hGap` 曾在 `114b090` 从 **70 压到 20**（为适配分支组），导致同一逻辑间距在缩放小的图上
    挤到 14.2px——"看着小"不是观感，是那次回归。
- 若某张图无法同时满足分支语义与可读性，必须停止并说明，不得靠"再调一下坐标"交付。

### R4（P0）不改变图的结构

- 排版只改坐标（与视口），**节点集合、边集合、节点参数一律不变**；不得增删节点、不得改写 `blockId`。

### R5（P1）交叉与宽度只记录

- 交叉边数、画布宽高**作为观察指标记录**，不设阈值；出现明显劣化时在验收记录里注一笔，不判红。

## 5. 验收标准

**先保形态，再看数值。** **数值达标但形态退化（退回被否的阶梯/碎片行）一律判红**——`412f015`
就是数值全绿（19.5px / 58.5px）而 7 列被排成 3×6 阶梯、主链两次向左下折回的例子。
任何一条语义或形态判据失败，即使不重叠、字号达标，也判不通过；
四张图（典型 8 节点、回退 7 节点、长链 14、长链 18）必须**全部**通过，不能只拿长链当证据。
